## 0. Locked 决策摘要

| 项 | 结论 |
|---|---|
| 项目 ≈ 工作区 | 同义词；顶栏 Tab = 本地文件夹舞台 |
| 左栏「项目」 | **方案乙**：P0 就有「项目」一级（任务板/排期/设置），对标 NewMax 长期放养 |
| 对话三轨 | 模型对话 / 智能体对话 / 小队对话 |

| 小队 | **模板** = 多个智能体 + 分工规则；进项目后实例化运行 |
| 直聊 | 可不建 Agent，直接选模型 |
| 模型供给 | CC Switch + 多 Provider；中转站后续；不做 Gateway |
| Skill | 目录兼容优先 + 自建市场渐进 |
| 桌宠 | 要（完成度，P1/P2） |
| 洞察 + 飞书/企微/Webhook | **预留**导航与设置位，P0 不实装 |
| 聊天形态 | 类似 IM：用户/智能体有头像框 |
| AI 搭建 | 用户可通过聊天让 AI 起草智能体/小队，确认后写入全局库 |
| Agent 默认 Skill/工具 | **进项目默认可用**（见 §5.6） |
| 权限权威 | **仅对话 Compose 一档**；Agent 不再单独配权限（见 §5.7） |
| 任务清单/分工 | 不限小队；单智能体/模型直聊也可出清单（见 §2.3） |
| 子任务呈现 | **默认仍在本对话**（卡片/内嵌进度），不默认新开对话（见 §5.8） |
| 推理强度 | Compose 可选，按模型动态档位（见 §2.2） |
| 直聊升级 | 用户主动 + AI 建议确认；禁止静默升级（见 §5.9） |
| 分屏 | **要**，对齐 NewMax：对话复制到右侧分屏 / 当前窗格打开；项目文件与对话左右分屏（见 §3.6） |
| 规格状态 | **Locked**（2026-07-22 用户认可） |

## 1. 整窗骨架（定稿线框）

```text
┌─ 顶栏：项目/工作区 Tab ──────────────────────────────────────┐
│ [ 官网改版 × ] [ 内部工具 × ] [ + 打开/新建 ]     🔔  ⚙     │
├────────┬─────────────────────────────────────┬───────────────┤
│ 左侧栏  │ 主舞台                               │ 右侧栏(可关)  │
│        │                                     │               │
│ 对话*  │  标题区 + 成员条(小队时)              │  见 §3       │
│  ·模型 │  消息流（头像 + 思考/执行/问询/分工） │               │
│  ·智能体│ Compose：对象→权限→Skill→输入        │               │
│  ·小队 │                                     │               │
│ 项目   │  或：智能体库 / 小队库 / 项目看板     │               │
│ 智能体 │                                     │               │
│ 小队   │                                     │               │
│ 能力   │                                     │               │
│  ·Skill│                                     │               │
│  ·浏览器│                                    │               │
│ 设置   │                                     │               │
└────────┴─────────────────────────────────────┴───────────────┘
* 默认首页 = 对话
```

### 1.1 左侧信息架构

| 一级 | 二级 / 内容 | 主舞台 |
|---|---|---|
| **对话** | 模型对话 / 智能体对话 / 小队对话 三个子栏 + 会话列表 | 聊天 |
| **项目** | 当前项目的聊天摘要入口、任务看板、排期、项目设置 | 项目视图（类 NewMax 长期放养） |
| **智能体** | 全局 Agent 库 | 配置页（人设/模型/能力/头像） |
| **小队** | 全局小队模板库 | 配置页（成员/分工/协作规则） |
| **能力** | Skill（目录+市场）、浏览器 Profile/Workflow | 管理页 |
| **设置** | Provider、CC Switch、主题、桌宠、权限默认、通知与洞察(预留) | 设置 |

### 1.2 顶栏 vs 左栏「项目」

- **顶栏 Tab**：我现在在哪个文件夹舞台（切换即换对话列表根、文件根）。
- **左栏「项目」**：在当前舞台里看任务板/排期/项目设置（NewMax 项目视图同构）。
- 未打开任何项目时：引导「打开文件夹」；可保留「收件箱」纯聊（无文件根则限制本地工具）。

## 2. 主舞台细线框（对话内）

### 2.1 消息流结构（单条助手回复）

对齐 NewMax，顺序固定：

```text
[智能体头像]  前端小张 · 2 分钟前
│
├─ (可选) ▼ 深度思考 · 8.2s          ← 有 reasoning 流才显示；P0 可隐藏入口
│            思考正文（可折叠）
│
├─ (可选) ▼ 执行过程 · 3 步 · 12s    ← 工具步骤；探索/修改/验证分组
│            ▸ 探索 · …
│            ▾ 读取文件 · package.json
│               路径 + 预览 + 复制 + 文件夹
│
├─ (可选) ── 任务分工卡 ──           ← 小队/复杂任务；见 §2.3
│
├─ (可选) ── 问询卡 ──               ← 需用户拍板；见 §2.4
│
└─ 正式回复正文（Markdown）
```

原则：

1. **思考 ≠ 执行 ≠ 正文**，三块分离（与 NewMax 一致）。
2. 无数据则不渲染空壳。
3. 完成后：思考/执行默认折叠；进行中可展开。
4. 头像：用户、智能体、小队成员各用自己的头像框；模型直聊用模型/产品默认头像。

### 2.2 深度思考 + 推理强度（比 NewMax 更明确）

| 点 | NewMax | Sync-Think 目标 |
|---|---|---|
| 数据源 | Extended Thinking / reasoning 通道 | 同；adapter 未接通前 **不假装有** |
| UI | 回复内可折叠块 + 耗时 | 同构：`深度思考 · Xs` |
| 强度控制 | 有「思考」菜单，且 **按模型动态档位**（自动/关/低/中/高/超高/极限等） | **明确做成「推理强度」选择器**，文案可比 NewMax 更直白 |
| 与模型关系 | 换模型后不支持的档位回退「自动」，不改写原选择 | 同 |
| P0 | — | Compose 露出推理强度；无 thinking 流则只影响请求参数，不渲染空块 |

**Compose 示意**

```text
推理强度: [ 自动 ▾ ]   ← 选项随当前模型变化
          自动 | 关闭 | 低 | 中 | 高 | （模型支持时）超高/极限
```

说明：NewMax **有**思考档位，只是产品文案叫「思考」而不是「推理强度」。你这边用「推理强度」更贴专业用户，能力对齐并允许按模型裁剪选项。

### 2.3 任务清单 / 分工卡（不限小队）

#### NewMax 何时会出现「清单感」？（调研结论）

文档里没有单独的「任务清单开关」，实际是 **多种机制叠出来的 UI**，所以你会觉得「有时有、有时没有」：

| 机制 | 何时容易出现 | 用户看到什么 |
|---|---|---|
| **会话任务清单工具** | 模型判断任务多步、需要跟踪进度时调用「创建/更新会话任务清单」 | 对话里的 checklist 式进度（为我批准下通常自动允许） |
| **`/plan` 规划模式** | 用户显式开规划，或输入含 规划/计划/方案 等词被提示 | 先出可审批 Markdown 大纲，确认前不落地 |
| **子代理** | 模型决定后台并行拆复杂活 | 子代理卡片：名/状态/独立工具史，结果回主对话 |
| **长期项目 `create_tasks`** | 在项目聊天里规划排期 | 任务进看板，不是普通对话清单 |
| **普通单步问答** | 一问一答、只读查询 | **通常没有**清单 |

判断主体主要是 **模型策略 + 用户是否进入规划/项目语境**，不是固定规则引擎。  
Sync-Think 应对齐这种「该出现才出现」，并加上你的编排增强。

#### 我们的产品规则（推荐）

| 对话类型 | 可以出现 | 谁确认 |
|---|---|---|
| 模型直聊 | 会话任务清单（单线程 checklist） | 用户；或「统筹 Agent」代确认（见下） |
| 智能体对话 | 同上；若该 Agent 角色=统筹/PM，可 **代审清单** | 统筹 Agent 可直接「采用/改后执行」 |
| 小队对话 | 任务分工卡（多 Agent 角色） | 默认问用户；若当前对象是统筹 Agent，可代审 |

**两种卡片不要混名：**

1. **会话任务清单**（单执行者，多步跟踪）— 对齐 NewMax session todo  
2. **任务分工卡**（多角色/多 Agent）— 你的差异化  

```text
┌ 任务清单 · 进行中 ─────────────┐   ← 单 Agent / 模型
│ ☑ 摸清 auth 目录结构            │
│ ☐ 抽出 session 中间件           │
│ ☐ 补测试并跑通                  │
└────────────────────────────────┘

┌ 任务分工 · 待确认 ─────────────┐   ← 小队 / 多角色
│ 1. 架构师 …  2. 前端 …  3. 审查 │
│ [采用并开始] [改后再确认] [不拆] │
└────────────────────────────────┘
```

#### 统筹智能体代审（你的需求）

若某 Agent 在配置里标记 `canApprovePlan: true`（或角色模板=「统筹/PM」）：

- 它在对话里 **可以直接**：采用清单/分工、修改后执行、取消拆分  
- 仍写审计事件：`approvedBy: agent:<id>`，用户可在过程/任务 Tab 回看  
- **不替代** 权限三档对危险工具的确认（权限仍只看 Compose）  
- 用户随时可在 Compose 把对象切回自己，或点「改为由我确认」

### 2.4 问询卡（对齐你图二 + NewMax 问询）

**何时出现**

- AI 需要用户在选项里拍板（方向/范围/技术选型/是否改生产…）  
- 危险操作确认（权限档为询问/为我批准时）  
- 浏览器卡点接管（验证码/登录）— 专用变体  

**形态**

```text
┌ 需要你确认 ──────────────────────────────────────┐
│ 登录重构有两种做法，我建议先做 A：                 │
│                                                    │
│  ○ A. 最小改动：只抽 session 中间件（推荐）        │
│     风险低，两天内可验收                           │
│  ○ B. 完整重写 auth 模块                           │
│     更干净，但影响面大                             │
│  ○ C. 先写测试再动代码                             │
│                                                    │
│  补充说明（可选）[________________]                │
│                                                    │
│  [ 确认并继续 ]      [ 跳过，你自行决定 ]          │
└────────────────────────────────────────────────────┘
```

**NewMax 对齐点**

| NewMax | Sync-Think |
|---|---|
| 系统通知「正在等待你的回复」 | 同；后台对话 + toast「查看」切回 |
| 问询时消息队列暂停 | 同 |
| 选项 + 推荐标记 | 同；**默认高亮推荐项** |
| 浏览器「我已处理完，继续」 | 问询卡变体 `takeover` |

**规则**

1. 问询未完成前，不自动开下一轮重工具。  
2. 「跳过」= 模型在无用户偏好下继续（写入事件：user_skipped）。  
3. 多选/单选由卡类型声明；P0 先做单选 + 可选补充文本。

## 3. 右侧边栏（对照 NewMax + Sync-Think 增量）

### 3.1 NewMax 右栏实际有什么

| 场景 | NewMax 右侧 |
|---|---|
| 点文件卡片 / `@` 文件 | **文件预览面板**（代码/MD/表格/PDF/图片/视频/HTML/SQLite…） |
| AI 改文件后 | 自动切到 **Changes**（变更列表 + diff） |
| 项目视图 | **项目文件**（变动文件 / 所有文件）→ 点开仍走预览；可与对话分屏 |
| 任务看板点任务 | **任务详情抽屉**（约 420px：状态/依赖/产出/历史） |
| 窄屏 | 自动收起；可浮层展开 |
| 无内容时 | 可不占位或显示工作区文件列表（视版本） |

另：**消息目录**在 NewMax 是对话**左侧刻度**，不是右栏。

### 3.2 Sync-Think 右栏目标（Tab 化）

默认 **按需出现**（有内容才推开；用户可钉住）。

```text
┌ 右栏 ─────────────────────┐
│ [ 文件 ] [ 变更 ] [ 任务 ] [ 过程 ] │
│  （开发者模式可多一个「诊断」）      │
│                           │
│  当前 Tab 内容…            │
│                           │
│  宽可拖；可关闭             │
└───────────────────────────┘
```

| Tab | 显示什么 | 何时自动打开 |
|---|---|---|
| **文件** | 当前预览文件；无选中时显示项目/工作区文件列表（P1） | 点击消息/过程里的路径、产物、文件卡片 |
| **变更 Changes** | 本轮/本会话 AI 修改的文件列表 + diff | `write/edit` 成功后（对齐 NewMax） |
| **任务** | 当前对话关联的任务/分工进度；小队子任务；点开详情 | 出现分工卡、委派、项目任务更新时 |
| **过程** | 与对话内「执行过程」同源的时间线（回看整轮） | 用户点「查看过程」或长任务进行中可选 |
| **诊断** | Run/Step/原始事件（仅开发者日志开） | 从不自动 |

### 3.3 各 Tab 细线框

**文件**

```text
package.json                    [系统打开] [文件夹] [复制路径]
┌──────────────────────────────────────┐
│ 语法高亮 / MD 渲染 / 表格…            │
│ （只读 P0；可编辑预留 P2）            │
└──────────────────────────────────────┘
若路径匹配产物 → 次要入口「在产物版本中打开」
```

**变更**

```text
本轮变更 · 3 个文件
  M  src/auth.ts      [查看 diff]
  A  src/auth.test.ts
  M  package.json
>6 个折叠「展开更多」
```

**任务**

```text
当前分工 · 进行中
  ✓ 架构师 · 边界说明
  ● 前端小张 · 改代码
  ○ 审查员 · 等待
[在项目看板中打开]
```

点某一任务 → 详情（状态、依赖、产出、关联对话）— 对齐 NewMax 任务详情面板。

**过程**

```text
第 1 轮 · 已完成 · 12s
  ▸ 探索 · 2 步
  ▸ 修改 · 1 步
  ▸ 验证 · 1 步
```

与对话内过程块 **同一 projection**，避免两套文案。

### 3.4 右栏与中栏分工（避免重复）

| 信息 | 中栏（对话） | 右栏 |
|---|---|---|
| 思考 / 执行摘要 | 主入口，跟消息走 | 过程 Tab 回看 |
| 文件正文 | 步骤内短预览 | 文件 Tab 大预览 |
| diff | 消息里变更卡片可点 | Changes 列表 + 对比 |
| 分工确认 | 问询/分工卡 | 任务 Tab 进度 |
| Run ID 等 | 默认不出现 | 诊断 Tab |

### 3.5 项目视图时的右栏

对齐 NewMax 项目：

- 右栏优先 **项目文件 / 变动文件**  
- 点任务仍可出任务详情  
- 聊天 Tab 与文件预览可左右分屏（见 §3.6）

### 3.6 分屏（对齐 NewMax，Locked）

NewMax 能力（文档）：

| 能力 | 入口 |
|---|---|
| 复制对话到右侧分屏 | 对话 tab 右键 →「复制到右侧分屏」 |
| 在当前窗格打开 | 最近对话右键 →「在当前窗格打开」 |
| 项目文件分屏预览 | 点项目文件 → 主区左右分：对话 \| 预览 |
| 窄屏 | 自动折叠侧栏/文件列表；可浮层 |

Sync-Think 目标：

```text
┌ 左窗格（主对话） ─────┬─ 右窗格（分屏） ──────────┐
│ 对话 A 消息流          │ 对话 A 副本 / 对话 B      │
│ 或 项目聊天            │ 或 文件预览 / Changes     │
└───────────────────────┴───────────────────────────┘
```

| 阶段 | 范围 |
|---|---|
| **P0** | 主舞台 + 右栏 Tab（文件/变更/任务/过程）已是「弱分屏」；文件预览不盖住对话 |
| **P1** | 真·双对话分屏：复制到右侧 / 关闭右窗格 / 拖宽 |
| **P1** | 项目：对话 \| 文件 左右分屏（NewMax 项目预览同构） |
| **P2** | 多窗格超过 2、布局记忆 |

原则：分屏是 **同一项目舞台内** 的布局，不跨项目乱挂会话。

## 4. 关键路径点击说明（验收线框）

### P-A 模型直聊
1. 顶栏选项目 → 左「对话 · 模型」→ 新建  
2. Compose 选模型 → 发送  
3. 中栏：执行过程折叠；点 read → 步骤预览；点路径 → 右栏文件  
4. 写文件 → 右栏自动 **变更**

### P-B 智能体聊
1. 左「智能体」→ 选「前端小张」→ 开始对话  
2. 或「对话 · 智能体」新建并选对象  
3. 头像框显示小张；权限默认用**项目覆盖或全局默认**

### P-C 小队分工（图一）
1. Compose 选小队「交付组」→ 描述目标  
2. AI 出 **任务分工卡**（建议 + 可改）  
3. 用户确认 → 成员条出现；子任务进右栏 **任务**  
4. 各成员过程在消息流带 `Builder ·` 前缀（多 Agent 时）

### P-D 问询建议（图二）
1. AI 插入 **问询卡**（推荐项标记）  
2. 系统通知（若在后台）

## 5. Agent / 小队全局数据模型（草案）

### 5.1 核心实体

```text
Provider / ModelCatalog     模型供给（CC Switch、手动 Provider）
        │
        ▼
Agent (全局智能体) ──────────────┐
  id, name, avatar                │
  defaultModelRef                 │
  defaultReasoningEffort?         │
  systemPrompt / persona          │
  defaultSkillIds[]               │  ← 进项目默认可用
  defaultMcpServerIds[] / tools   │  ← 能力白名单，不是权限档
  canApprovePlan: boolean         │  ← 统筹代审清单/分工
  createdFrom: manual | ai-draft  │
        │                         │
        │ members[]               ▼
        └──────────────► TeamTemplate (全局小队模板)

                           members: [{ agentId, roleLabel, duty }]
                           collabPolicy: serial|parallel|graph

Project / Workspace (舞台)
  id, name, rootPath, icon
  defaultTalkTarget: model|agent|team + ref
  defaultPermissionMode?          ← 仅「新对话默认权限」，可被 Compose 改
  projectSkillIds[]?              ← 项目额外 Skill（并入，不取代 Agent 默认）

  id, projectId

TeamRun / TaskListRun（本对话内的执行单元）

  kind: checklist | team_division
```

### 5.6 Agent 默认 Skill / 工具在项目里能不能用？

**能。默认就应该能用。**

| 来源 | 进项目后 |
|---|---|
| Agent.`defaultSkillIds` | **自动可用**，无需每次点选 |
| Agent 绑定的 MCP/工具面 | **自动可用**（仍受对话权限档约束「能不能真执行」） |
| 项目 `projectSkillIds` | **追加**可用 |
| 消息级 Skill 点选（NewMax 式） | **本条追加**，发送后消费或按产品定是否粘滞 |
| 用户在会话里关掉某 Skill | 本会话禁用，不改 Agent 全局 |

原则：

> **Agent 的 Skill/工具 = 能力装备；对话权限档 = 能不能扣扳机。**  
> 进项目不是卸装备，只是换场地。

若某项目要收紧：用 **项目追加/禁用 Skill 列表** 或换一个更窄的 Agent，**不要**再给 Agent 配第二套权限矩阵。

### 5.7 权限：采纳你的简化（强烈推荐）

你提的方案比多层覆盖更好，**采用为 Locked：**

```text
对话 Compose 权限档（询问批准 / 为我批准 / 完全访问）
    =
本对话里所有模型 / Agent / 小队成员 的执行权限
```

| 不要 | 要 |
|---|---|
| Agent 上再配「这个人只能只读」权限产品 | Agent 只配 **能力**（Skill/MCP/人设/模型） |
| 项目里再嵌套 agent 权限 overrides | 项目最多提供 **新对话默认权限** |
| 小队成员各玩各的权限档 | 成员全部继承 **当前对话权限档** |

生活化理解：

- 你把房间门禁设成「为我批准」  
- 请来的前端小张、审查员 **同一道门**  
- 小张「会不会写 React」是技能；「要不要问你才准删文件」是门禁  

新对话权限初值：

```text
Compose 当前选择
  ← 若用户没动过：项目 defaultPermissionMode
  ← 若项目未设：设置里的全局默认（建议「为我批准」）
```

中途改 Compose 权限 → **下一轮回复**生效（对齐 NewMax：不改正在打的工具）。

### 5.8 子任务怎么触发？在本对话还是新对话？

**推荐默认：始终在本对话内完成（NewMax 子代理/会话清单同构）。**

| 步骤 | 行为 |
|---|---|
| 1 触发 | 模型调用「更新任务清单」/ 提出分工；或用户说「拆一下」；或选了小队 |
| 2 确认 | 清单/分工卡；用户确认 **或** 统筹 Agent 代审 |
| 3 执行 | 为每个 item 开 **Run/Step**（逻辑子任务），**消息仍写在同一 Conversation** |
| 4 UI | 成员/条目进度嵌在原消息流 + 右栏「任务」 |
| 5 可选 | 用户点「在项目看板同步」→ 复制到项目任务（不强制新开聊） |
| 6 例外 | 仅当用户点「用新对话跑这一步」才 `fork` 新 Conversation（P1） |

和旧 Sync-Think「子任务=新任务实体」的关系：

- 内部仍可有 `TaskItem` / worktree 隔离（工程需要时）  
- **产品叙事**不要变成「又开了一堆会话」；用户感觉是 **一条对话里的分工进度**

### 5.9 模型直聊 → 智能体 / 小队：如何触发？

**禁止 AI 静默改 track。** 两种合法触发：

| 方式 | 怎么触发 | 流程 |
|---|---|---|
| **A. 用户主动（主路径）** | Compose「升级 ▾」或标题栏「转为智能体对话 / 组成小队」 | 选已有 Agent/小队或新建 → 确认 → `track` 变更，**保留消息历史** |
| **B. AI 建议（辅助）** | 模型识别复杂协作意图 → 插入建议卡 | 「建议交给交付小队，是否升级？」→ 用户点是才升级 |

AI 可建议的信号（示例，非硬编码唯一规则）：

- 用户明确说「组个队 / 叫审查一起来」  
- 多角色动词密集（设计+实现+测试+发布）  
- 已连续多轮且清单项 > N  

**不要**仅因任务稍难就自动升级。

### 5.3 会话三轨

| track | targetRef | 列表归属 |
|---|---|---|
| `model` | providerModelId | 对话 · 模型 |
| `agent` | agentId | 对话 · 智能体 |
| `team` | teamTemplateId（+ 可选 activeTeamRunId） | 对话 · 小队 |

### 5.4 与执行系统的关系

- **Agent** 提供：默认模型、人设、Skill/工具装备、是否能代审  
- **Conversation.permissionMode** 提供：唯一执行门禁  
- **TaskListRun / TeamRun** 提供：本对话内清单或分工状态  
- 逻辑子任务 Run 挂 item 上，默认不新建会话  
- **requiredEvidence**：后置  

### 5.5 AI 创建流

```text
用户自然语言
  → AI 产出 AgentDraft | TeamDraft（结构化）
  → 对话内确认卡
  → 写入 Agent / TeamTemplate
  → 可选：立刻创建 Conversation 并跳转
```

草稿必须用户确认，禁止静默写入全局库。
