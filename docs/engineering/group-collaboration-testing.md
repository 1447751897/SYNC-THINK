# SYNC-THINK 群聊协作测试

## 本轮范围

保留现有群聊页面、智能体和模型配置。新增本群描述、协调员讨论决策、真实成员单人/并行/顺序发言、直接交接、讨论失败后的有界协调，以及公开/私人消息受众投影。正式工作的产物提交、审核、检查点和交接沿用原有流程。

这不是完整的“谁是卧底/狼人杀”：自动发牌、投票、淘汰、胜负判定和严格的私有游戏状态尚未接入。普通私信也不是面向本机管理员的加密存储。

## 构建和启动

先暂停正在执行的工作，退出正在使用的开发版。PowerShell 在项目根目录运行：

```powershell
Set-Location D:\projects\SYNC-THINK
pnpm exec tsc -b apps/runtime apps/desktop
pnpm --filter @sync-think/desktop build
$env:SYNC_THINK_RUNTIME_FORCE_RESTART = '1'
pnpm dev:desktop
```

强制刷新只针对这次启动的开发 runtime，避免旧常驻进程继续运行旧代码。不要在仍有执行任务时重启。需要在前台运行的终端保留打开；退出后可移除该环境变量。以上是源码开发版路径，不是发布、下载更新或安装新版本。

## 准备测试群

1. 使用三个已配置可用模型的智能体。以下用“研究员”“审查员”“协调员”举例，发言名字必须替换为你实际使用的成员名。
2. 进入现有群聊 → **成员 → 执行设置**。
3. 旧群手动开启 **协调员组织群讨论**；新建群默认开启。
4. 在 **本群协作规则 → 群描述** 保存：
   > 本群负责讨论产品方案。默认研究员先提出建议，审查员在研究员实际回复后提出质疑，协调员最后总结并向用户询问未解决的问题。每人只说自己的部分，不代替别人发言。用户指定并行时允许独立观点并行。需要补充时成员可以直接交接给另一成员；出现阻塞由协调员说明并安排下一步。
5. 在“高级协作设置”开启 **允许群内智能体互相咨询**，以便测试非协调员之间的直接交接。描述只影响本群，不修改小队模板或个体身份。

## 逐项验收

### 顺序讨论与共享上下文

发送模式选“讨论”，消息不加 @：

> 按本群描述的顺序讨论：如何让群聊更像成员之间真正的交流？每人一句即可，审查员要指出研究员实际说出的一个观点，协调员最后归纳。

应观察到真实成员依次发言。执行详情能看到协调路由及贡献状态；审查员应基于已经成功返回的研究员消息，而不是一段提前编好的多人台词。内部路由 JSON 不应成为聊天回复。

### 明确 @ 仍然直达

用输入框的 @ 候选选择研究员：

> @研究员 只回答你自己的看法，其他成员这次先不发言。

只应唤醒该成员，不为了形式补全全员。后续回复某条消息仍面向该消息的作者。

### 并行观点

不加 @：

> 请研究员和审查员各自独立提出一个群聊交互建议，这一轮并行，不要等对方；协调员不用额外总结。

两位成员的贡献应独立排队/运行。实际并行度受并发上限、资源锁和模型服务速度影响，不承诺两个气泡同一毫秒出现。

### 成员直接交接

发送：

> @研究员 先提出一个方案，再请审查员补充，交接后结束，不用等回执。

可通过真实 `collaboration_send_message(deliveryMode="handoff")` 交接；普通讨论的最终公开回复也支持独立行首 `@审查员 请补充`。正文提到名字或代码块中的 @ 不触发。不要把这里的文本交接当作文件生产派工。

### 私信与回复

输入框工具条选择 **私信 · 先 @ 接收者**，用 @ 候选指定研究员，使用“聊天”或“讨论”：

> 这条仅给你：本次测试暗号是 PRIVATE_CANARY。请私下回复收到，不在公开讨论中引用暗号。

应看到“私信 · 仅参与者可见”标记。对这条点击“回复”时，可见范围保持私人。另一个成员的模型上下文不应得到这条消息。作为消息发送者的你仍然能看到自己的私信；这与“用户看不到主持人发给其他成员的牌”是不同需求。

普通 GUI 不展示别人的私人消息；本机数据库/通用执行记录仍由本地账号管理，不作为严格游戏保密证明。也应注意：群内公开消息不会因为 @ 某个成员就自动变成私信。

### 暂停与续做

发送一条多成员顺序讨论，在协调员或首个成员运行时点击群聊“暂停”。等到“已暂停”再“继续”。不应在暂停后偷偷唤醒后续成员；成功返回过的贡献不应重跑，未完成的尝试应留下中断记录。

### 失败后的协调

使用测试专用的研究员智能体，临时选择一个不可用的模型配置（不要修改其他群正在使用的成员），再发顺序讨论。失败后应出现一次协调员处理，明确阻塞和剩余成员；协调员不应假冒研究员输出成果，后续顺序成员不应绕过失败前置。测试后恢复模型配置。如果协调员本身也不可用，只会保留真实失败供手动恢复，不伪造协调回应。

### 正式工作回归

绑定一个测试项目目录，发送模式选择“工作”：

> 请研究员生成一份群聊改进建议文档，交给审查员审核，最后由协调员向我报告。以实际提交的文档版本作为审核依据。

应沿用原来的工作目标、产物提交和审核交接；在“成果”中打开实际文档，在执行详情核对成员、尝试和依赖。只发“完成了”但没有约定产物不算交付。私信 + 工作模式会提示改用公开的正式工作，避免私人文本进入共享任务目标。

- `apps/runtime/src/collaboration-group-planning.integration.test.ts`：真实 SQLite＋原生 Runtime＋脚本化 Provider，验证零工具决策、真实顺序发言、前序消息和私人上下文隔离。

- `packages/protocol/src/collaboration-group-config.test.ts`：配置 CAS、私信协议、宿主字段防注入。
- `apps/desktop/src/renderer/shell/GroupConversationSettings.test.tsx`：保存、旧群开关、冲突和繁忙状态。
- 现有 `CollaborationChatView.test.tsx` 追加私信发送/回复回归。

Windows 下若 esbuild 处理大型 runtime 源码时报告临时文件删除“Access is denied”，测试命令临时设置 `TEMP` / `TMP` 为项目 `.data/group-test-temp` 后重试。不要删除或重置用户数据库来处理这个构建工具问题。

自动测试使用脚本化执行器，不调用你的付费模型；真实模型是否准确遵从群描述，需要按上述步骤验收。
