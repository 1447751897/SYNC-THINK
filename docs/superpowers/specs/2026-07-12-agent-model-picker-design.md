## 1. 需求理解（确认）

你要的不是「Compose 里塞一个选模型弹层」，而是：

```text
智能体中心
├─ 能看到自己创建的「全部智能体」
└─ 点击某一个智能体
   ├─ 看到它的工作与上下文
   │   · Tasks（相关任务）
   │   · 指令 / 人设 / 输出约定
   │   · Skills（白名单）
   │   · MCP / 工具
   │   · 记忆 / 凭证（可后续）
   └─ 配置「运行时」= 用哪个模型跑
       1. 先选「分组」
       2. 再选「供应商」
       3. 再选「模型」
```

**可以，完全理解。**  
这和产品设计 §5.3 Agent model binding、§8 Agent definition、§9 Skill 一致：  
配置挂在 **Agent** 上，对话只是使用该 Agent 的默认绑定。

## 2. 名词对齐（避免和 CC Switch 混）

| 你说的 | 产品里是什么 | Demo / UI 展示 |
|--------|--------------|----------------|
| **智能体** | `Agent` / `AgentVersion` | 列表里的一张卡 |
| **工作** | 该 Agent 参与的任务、最近 Run、能力摘要 | 详情「概览 / 工作」 |
| **Tasks** | 关联或最近打开的 Task | 「任务」页签 |
| **指令** | Agent 的 instructions / role / 输出约定 | 「指令」页签 |
| **Skills** | Agent allowlist 的 SkillVersion | 「Skills」页签 |
| **运行时** | 默认模型绑定 + 可选 fallback / 凭证组 | 「运行时」页签 |
| **分组** | 第一层目录：应用族 / 导入分组（Codex、Claude Code、Kiro、其他…） | 运行时第 1 列 |
| **供应商** | Provider（KMKAPI-CODEX、Unity2.Ai、Official…） | 运行时第 2 列 |
| **模型** | Provider 下的 model id → 存 `defaultModelId` | 运行时第 3 列 |

说明：

- **分组 ≠ 凭证组**。凭证组仍在「凭证」里单独绑（§5.4）。  
- **分组**在这里 = 选模型时的第一层分类（对齐 CC Switch 左侧 app / 你的「先分组」）。  
- 值仍只存 **modelId**（+ 可选 credential group / pin），不存三层路径字符串。

三栏顺序（按你的要求锁定）：

```text
分组  →  供应商  →  模型
(Codex)  (KMKAPI-CODEX)  (gpt-5.4-mini)
```

## 4. 关键流程

### 4.1 浏览全部智能体

1. 打开「智能体中心」  
2. 左侧/主区列表展示全部 Agent  
3. 点击一张 → 进入该 Agent 详情（右侧或整页）

### 4.2 看这个智能体在干什么

| 页签 | 用户看到什么 |
|------|----------------|
| 概览 | 角色、运行时一行、最近任务、Skill/MCP 计数、能力就绪 |
| 任务 | 该 Agent 参与过或关联的 Task 列表，可点开 |
| 指令 | 系统指令 / 角色说明 / 输出约定（可编辑） |
| Skills | 已绑定 Skill；从库添加/移除（安装 ≠ 白名单） |
| 工具 | MCP 白名单与策略摘要 |
| 运行时 | 三栏选模型 + 当前路径 + 保存 |

### 4.3 配置运行时（你强调的）

1. 打开该智能体 → **运行时**  
2. **分组**：如 Codex / Claude Code / Kiro / 其他  
3. **供应商**：该分组下的 Provider 列表  
4. **模型**：该供应商下的模型；点选 = 草稿默认模型  
5. **保存绑定** → 写入 Agent `defaultModelId`  
6. 可选：Fallback 链、暂停失败、凭证组（次级折叠，不挡主路径）

## 6. 与现有实现的差距

| 现状 | 目标 |
|------|------|
| 基本只有 **一个** Agent 绑定面板（`getAgent` 单例感） | **智能体列表** + 选中详情 |
| 模型用下拉 / 弹层 `ModelPathPicker` | 详情内 **运行时** 页签，三栏内嵌 |
| 顺序曾用「应用→分组→模型」文案 | 文案统一为 **分组→供应商→模型**（数据仍 surface→provider→model） |
| Skills/MCP 挤在同一长表单 | 拆成详情页签，按需打开 |
| Compose 抢选模型 | Compose 轻量；管理回智能体中心 |

数据层后续需要（实施时）：

- `listAgents` / `getAgent({ agentId })` / `createAgent`（若尚无列表 API）  
- 详情聚合：binding + skills + mcp + 关联 tasks 摘要  
- 现有 `updateAgentBinding` 可继续承载运行时保存  

M1 若暂只有单 Agent，Demo 与 UI 仍按「多智能体」做；列表可先只有 1 个，结构预留扩展。
