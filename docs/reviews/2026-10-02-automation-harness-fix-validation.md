## 已修复

### 1. 普通模型 / 智能体定时轮次的持久化恢复

- 宿主在调用 Provider 前，将 `scheduledTaskContext`（版本 1）和完整 Run 一起写入执行日志。
- 冻结原任务、轮次 firedAt、专属 conversation/thread、技能版本及浏览器流程版本；首次惰性创建的会话 ID 也纳入快照。
- 恢复时重新登记任务并发名额、冻结权限/能力上下文和最终历史回填；不会把定时任务当普通聊天恢复。
- 已停用、会话范围或关键配置改变、依赖不就绪的轮次，记录具体阻塞原因。
- 保留原有 **5 分钟无活动自动恢复窗口**。过期请求或旧版本缺少快照的请求保留结果并暂停，而不是猜测配置、盲目重放外部副作用。本轮没有实现无限期自动重放。
- 小队沿用已有 Collaboration Host 的恢复机制，本轮没有让原始 Provider Run 越过小队宿主恢复。

### 2. 登录续跑与未来触发规则分离

- Skill 版本纳入登录交接的配置指纹；改动关键配置后，交接仍保留，继续操作会给出核对提示。
- 续跑使用原轮次的冻结目标、权限、技能、Profile、产物配置和运行日期，回到原专属会话。
- 用户等待期间更新的未来时间规则/时区继续生效；续跑旧轮次不会覆盖更新后的下一次触发时间。
- 后续定时 tick 合并跳过不会覆盖“等待操作”的顶层结果；跳过原因仍保留在历史中。

### 3. 正确区分等待、阻塞与交付核对

新增历史/页面状态：

- `waiting_input`：等待操作，例如登录交接。
- `blocked`：配置或恢复预检阻塞。
- `reconciling`：发件已发起但结果/回执待核对；停止自动重发。

DB0067 在事务内扩展历史状态约束并保留旧行、索引和历史文字；不将旧失败记录悄悄改成成功。迁移器对已有数据库的备份行为保留。本轮未对正式数据库执行迁移。

### 4. 可选的宿主结构化业务验收

原能力绑定编辑区增加 `automation.acceptanceChecks`：

- `minimumRows`：1–10000 条非空白数据行，表头不计；数值 `0` 计入数据。
- `requiredColumns`：1–128 个非空、不重复的列名。
- `dateColumn`：每条数据须填写原 firedAt 在原任务时区的日期，格式 YYYY-MM-DD。
- `sourceUrlColumn`：每条数据须填写合法 HTTP(S) 来源地址。
- `minimumSlides`：1–100 页。

关闭相应输出格式会清除对应规则；所有规则可清空，无自动默认值。前后端共用严格解析，规则没有对应输出格式时阻止保存。

宿主在真实导出前核对传入的数据。失败返回 `automation.acceptance_failed` 及具体检查结果，不写成功文件/回执；智能体可以在同一轮修正后重试。成功证明绑定实际导出文件、hash、冻结规则和触发日期。最终收尾和发件门禁重新核对真实文件的 size/hash，缺少宿主证明、旧轮文件、被修改或已删除文件均不算完成。

自然语言 `acceptance` 保留为工作/人工质量要求，**不是已经被程序完整证明的硬规则**。来源 URL 校验只证明地址语法，不证明内容真实、来源权威、榜单时效或内容质量；这些仍需采集和核查步骤。

### 5. 持久化邮件并发防重

- 发件读取/校验附件后，通过 SQLite `compareAndSet` 原子地领取本轮发件资格，再调用实际 connector。
- 两个成员针对相同证据版本竞争，只有一个发起发送；另一个得到状态冲突/已有回执，不重复发送。
- `sending` 在外部调用前持久化；断连、无回执或结果未知进入待核对，不自动重发。
- 发件已开始后锁定本轮产物；导出期间若发现邮件已经发起，新文件不加入交付证据。
- 该机制是本轮持久化防重和人工核对保障，**不宣称第三方邮件服务具备端到端 exactly-once**。

## 重启后的手动测试建议

1. **正常交付**：在原定时任务编辑器选择模型、智能体或小队，声明表格/PPT输出，并配置最少行数、必需列、日期列和来源列。先运行一次，核对真实产物与历史结果。
2. **不达标后修正**：用测试任务要求最少 3 行，在指令中安排“先尝试导出 1 行，读取宿主反馈，再补齐 3 行并重试”。第一次应返回具体验收错误，无成功产物/邮件；同一轮自动修正后才进入交付。若已结束失败轮次，则修改任务后重新触发，用新轮次验证，而不是把普通聊天当成旧轮次继续。
3. **登录继续**：用专用测试 Profile 触发需要登录的页面。应显示等待操作；后续 tick 不重复创建登录交接。完成登录后继续，仍归属原轮次和会话。
4. **冻结配置与未来日程**：等待期间改技能、目标或 Profile，应要求核对而非静默使用新配置；只改未来时间规则/时区，原轮次仍使用原配置，但未来触发时间保留新设置。
5. **交付待核对**：用本地/测试邮件连接器模拟无回执或断连，应进入待核对，不自动重复发送。
6. **恢复**：在隔离测试环境让 Provider 保持执行，保存数据库后模拟 Runtime 退出/恢复。短时恢复应继续原轮次、占用并发名额并回填历史；过期或改配置应显示明确阻塞。不要用正式账号的外部副作用做崩溃实验。

本轮没有开启任何真实定时器、扩大账号访问范围或改变审批偏好。正式账号级采集、登录验证与真实 Gmail 投递留给加载新构建后的用户验证。
