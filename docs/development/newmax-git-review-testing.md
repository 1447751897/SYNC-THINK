# 输入框 Git 状态栏与审阅面板验收

在绑定了本地 Git 仓库的工作区中测试。输入框上沿展示项目、Local、当前分支和未提交文件数量。普通目录不展示 Git 状态栏。

1. 点击「N 个未提交」：右侧打开对应仓库的审阅页。点击项目名称打开工作区搜索菜单；点击分支名称就地打开分支菜单，Esc 关闭；点击 Local 打开工作环境菜单。切换工作区后再次打开审阅，应显示新仓库的数据。
2. 用编辑器修改一个已有文件、新建一个文件：状态栏与右侧列表自动更新。点击文件名展开有颜色的 Diff；滚动文件列表时，底部提交标题、描述和按钮始终可见。
3. 勾选一个文件：实际执行 Git 暂存。取消勾选：实际取消暂存。搜索文件后点击「全部」，仅作用于搜索结果。列表中的已选状态与 Git 暂存区一致。
4. 部分暂存：先修改并暂存一个文件，再修改同一个文件。该路径只计数一次，显示半选状态；展开后可切换「已暂存（本次提交）」与「未暂存」查看两个版本，也可直接取消该文件暂存。
5. 在测试分支填写提交标题和可选描述后提交：只有暂存区内容进入提交，未暂存内容保留；历史中出现新提交，未提交数量随之更新。没有暂存文件、存在冲突或普通提交被进行中的 Git 操作阻止时，按钮不可用。
6. 点击「抓取 origin」（仓库的默认远端名称可能不同）：成功后显示实际抓取时间。推送、拉取、分支和工作副本操作使用现有 Git 后端。
7. 切换深色、浅色并缩窄侧面板：文件名截断、操作按钮和底部提交区仍可使用。

勾选代表真实 Git 暂存，不是独立于 Git 的临时 UI 选择；提交会包含仓库中已经暂存的内容，按钮显示对应文件数。

本次验证：组件与 Git 回归测试；独立 Electron 验证使用临时 Git 仓库和本地裸仓库，覆盖实际暂存、提交、Diff、抓取、外部编辑刷新、切换仓库及深浅色布局。验证过程没有提交或推送 SYNC-THINK 工作区的改动。

## 状态栏菜单与文件类型图标

- 项目菜单：工作区顺序保持不变；搜索可匹配名称和路径，选中项显示勾号。「新建工作区」打开目录选择器并进入新工作区。
- 分支菜单：搜索、当前分支标记、默认/最近/其他分组以及真实提交日期。默认分组取自仓库远端 HEAD 配置。支持新建并切换分支、选择合并目标后确认合并。
- 未提交改动：切换分支时选择「保留改动并切换」，应保留已暂存版本、未暂存内容及新文件，成功后不会留下本次使用的 stash。
- Local 菜单：显示主目录和已有 worktree。新建 worktree 时输入分支、目录，点击「创建并打开工作区」立即创建并进入对应工作区；从当前提交开始，原目录的未提交改动保留在原处。可以在同一菜单返回 Local。
- 键盘与布局：搜索框自动聚焦，方向键移动，Enter 选择，Esc 关闭并恢复入口焦点。深浅色、窄窗口下菜单都应在可视区域内。
- 图标：JSON（包括 package.json、.mcp.json）为黄色花括号，Markdown 为蓝色 M 与向下箭头，JS/MJS/CJS 为黄色 JS，TS/MTS/CTS 为蓝色 TS，TSX/JSX 为 React 图标。审阅、文件树、文件标签和文件引用共用同一映射。
