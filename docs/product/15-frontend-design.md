## 0. 设计授权与质量标准（2026-07-11 确认）

```text
结构：V3 三栏信息架构 Locked（左项目任务树 / 中完整聊天 / 右可折叠轨迹 / 完整浅深主题）
视觉与页面表达：不锁定 V3 的“朴素原型观感”
设计主导：Claude 对页面视觉、组件质感、交互动效、记忆点拥有原创设计权
质量目标：可获奖级（award-level）专业工具设计 — 不是模板后台，不是聊天套壳
用户观感与体验感优先于“看起来像做过就行”
```

### 0.1 可获奖级定义（本项目）

页面设计完成时，必须同时满足：

1. **一眼可识别**：3 秒内能看出这是 SYNC-THINK，而不是通用 Chat UI / 通用 Electron 壳。
2. **状态可感知**：Agent 交接、上下文转移、审批暂停、产物生成，不看文案也能感到“系统在做什么”。
3. **质感可停留**：表面、边框、字体、间距、微光与层级经得起长时间工作，不廉价、不塑料。
4. **交互有想象力**：关键路径有原创仪式感（开任务、批计划、看上下文、收轨迹），但服务于理解，不炫技。
5. **功能不让位**：再美也不能牺牲完整历史、可折叠轨迹、可检查 Manifest、键盘与无障碍。
6. **浅/深双主题都完整**：不是改几个色值的 dark mode，而是两套都被认真设计的完整皮肤。

### 0.2 Claude 设计主导规则

1. **旧原型只提供 IA 与功能清单**，不提供最终视觉答案。禁止把 V3 HTML “换皮上线”。
2. 每个首版页面至少有 **1 个记忆点**（signature moment），例如：
   - Context Continuum（上下文连续轨）的物质化表达
   - Agent 交接时的“上下文丝带/接力”动效
   - 计划批准的庄重但克制确认态
   - 轨迹折叠时的空间呼吸变化
   - Artifact 版本像底片/印样一样可对比
3. 允许大胆构图、非对称节奏、材质层次、定制排版；**不允许**破坏 Locked IA。
4. 拒绝无信息量装饰：加任何光效/纹理/动效前先回答「用户从中得到什么」。
5. 基础组件（Button / Input / Dialog / Message / Trace item）也必须原创，不只做布局层。
6. 实现时先设计再堆功能；若工期冲突，优先保证主工作台与 Context 体验的完成度。

### 0.3 创意方向（推荐推进，可在视觉 refinement 中强化）

工作标题：**“Continuum Bench / 连续工作台”**

```text
概念隐喻：
  - 不是聊天泡泡墙，而是一张可持续推进的思维工作台
  - Context rail = 任务的时间连续体与证据带
  - Agent = 带有稳定身份的协作者，而非彩色头像贴纸
  - Run trace = 可展开的执行底片 / 事件显影

视觉语法：
  - 矿物中性底（绿灰/石墨）+ 少量精密强调色
  - 纸感与金属感并存：聊天区更“可读”，工具轨更“仪器”
  - 细线、内阴影、微噪声、克制高光建立质感
  - 大呼吸区留给主对话；次级信息用密度换清晰，而不是堆卡片

交互语法：
  - 空间会呼吸：折叠轨迹、展开计划、打开 inspector 时有明确空间重分配
  - 交接可看见：上下文从 A Agent 到 B Agent 有可追踪的视觉路径
  - 批准有重量：危险/关键批准不是普通小按钮
  - 恢复有记忆：重启后回到工作的“未完成感”被温柔提示，而非冷冰冰 toast
```

## 0.4 官网与云端账号（2026-09-07）

- 官网是独立公开介绍页，参考 Multica 的全幅首屏、真实产品演示、能力说明和登录入口。品牌、文案、素材使用 SYNC-THINK 自有内容。桌面工作台的信息架构仍由原规则约束。

- 演示包含 13 个场景：完整流程、任务进度、提问、方案审批、工具审批、思考与工具、代码与文件、流式输出、失败重试、浏览器接管、桌面等待、需求队列和目标模式。实际用户操作推进内存状态，支持修订版本、拒绝、取消和重试；不调用真实模型、Runtime 或账号。文件在原生右侧工作台展示，窄屏停靠下方，不遮盖会话；支持标签、文件列表和调整尺寸。输入栏复用当前添加、权限、技能、身份、模型/思考强度和上下文菜单；用户主动选择的图片只读入页面内存，不上传。已下线的历史任务入口不在演示中挂载。外层播放控制不改变原始卡片样式。
- 账号页采用居中窄表单、明确标签、提交中/错误/邮件已请求/会话过期状态，覆盖注册、邮箱验证、登录、找回、重设密码及退出。密码为 12-128 字符。

- 云端账号首版只管理身份；下载页明确 Windows Alpha 状态，云同步与远程执行在 FAQ 中标为后续能力。

## 4. 色彩策略

以 V3 的中性绿灰为**基因起点**，但允许在保持识别的前提下提升对比、材质与强调色精度。完整浅/深两套 token 见 `16-shell-design-tokens.json`（改 JSON 后 `pnpm tokens:css` 生成 `apps/desktop/src/renderer/shell/tokens.css`）；视觉 refinement 时可进化 token，不可退化成分裂主题。现行落地色系为高对比中性绿灰 + 墨绿强调，避免大面积米黄使层级和文字对比变弱；`skins` 段预留自定义配色 / 换肤。

```text
主色：石墨工作色（浅深反转用于强操作）
辅助色：绿灰边栏与表面体系
强调色：
  - continuum/success：绿松石进行色
  - agent lanes：有限的身份色带（≠唯一状态）
  - warning / danger：高可辨且不刺眼
背景色：浅工作纸感 / 深矿物底
文本色：高对比主文 + 次级说明
状态色：success / warning / error / info 分离，并配合图标/文案
需要避免：
  - 深侧栏+浅画布分裂主题
  - 赛博霓虹、渐变光球、bokeh、无意义大色块
  - 仅靠颜色表达状态
  - 廉价纯白卡片墙 / 纯黑死板暗色
```

## 5. 布局原则

```text
导航结构：
  - 左：Projects → nested Tasks；项目可选绑定一个本地文件夹；底部 Agent/Skill/设置入口
  - 中：完整可滚动对话 + 顶部 Context Continuum + 底部 compose（项目 / Agent / 模型上下文入口）
  - 右：任务 / Run 信息栏（默认显示任务进度，可折叠；执行详情按需打开，记 Workspace 偏好）
页面宽度：桌面自适应；主阅读列有最优行长，但整体窗口要被信息填满，避免两侧空洞
内容布局：三栏可呼吸；折叠轨迹时中栏扩展，要有空间过渡
列表/表格：库与设置用精密列表/详情，不是装饰卡片堆
表单：分区、可扫描、危险项有重量
空状态：有场景插画式的克制空态 + 单一明确下一步；不是营销页
```

## 5.1 内核选择器

模型选择器中的“内核”列表沿用紧凑的品牌列表表达：每行使用内核专属图标、名称和第二行安装状态/版本信息；当前项使用浅色内嵌选中底和左侧勾选标记。内核图标本体与外层均使用透明画布，不加边框、底色或阴影；ClaudeCode 只显示橙色放射形 Claude 标志，GPT 只显示单色 ChatGPT 结形标志。GPT 与 Sync-Think 均使用主题文字色蒙版，浅色为黑色、深色为白色；ClaudeCode 在两种主题下保持橙色。用户可见名称为 Sync-Think / ClaudeCode / GPT / Pi；内部 kernel id 与数据层级保持不变。

## 5.2 新建对话、设置页与换肤边界

1. 新建对话空态直接提供可工作的 Composer，不做功能残缺的占位输入框。首轮必须可选择内核和模型、添加/粘贴/拖放图片、输入 `/` 选择命令或已启用 Skill，并可切换规划/执行模式；首条消息携带这些真实选择进入 Runtime，创建正式 Conversation 后保持一致。
2. 空态与正式 Composer 共享同一交互语言、图标尺寸、菜单层级和响应式规则。图片-only 首发可用；附件必须支持预览和逐项移除；`/plan <需求>` 直接以规划模式提交，`/plan` 与 `/execute` 只切换本地工作模式。
3. 设置页使用固定导航、独立纵向滚动正文和稳定底栏。底栏与正文同色，左右内边距 28px，完成按钮不得贴着弹窗圆角或被底栏固定高度裁切。页面、导航、正文和模型配置区都必须允许子项收缩；除表格、代码等明确所有者外，不出现页面级或设置 Dialog 级横向滚动条。
4. 组件不得自行推导主题色。表面、文字、边框和交互态只消费语义 token；控件、控件 hover、选中、选中边框和焦点分别使用 `control`、`control-hover`、`selection`、`selection-border`、`focus-ring`，后续皮肤通过 token 生成器和 `data-skin` 覆盖，不增加组件级主题分支。

### 5.3 设置数据页

1. “数据”页以本机 NewMax `1.1.14` 的实际 `DataTab` 和 DS 组件为基准：正文左右内边距 `24px`、顶部内边距 `15px`、卡片间距 `16px`，依次展示云端同步、数据迁移、数据备份、存储管理和清空本机数据。正文独立纵向滚动，底栏和完成按钮固定。
2. 卡片使用 `filled` surface、`18px` 圆角和 NewMax `elevation-100` 轻阴影，不绘制常规边框，也不锁定猜测高度。卡片内边距 `16px`、标题与正文间距 `8px`；标题、行标题、辅助文字分别为 `14px`、`13px`、`11px`，多行正文和操作自然撑开卡片。
3. 卡片正文纵向间距为 `12px`；小按钮和选择器统一高 `28px`，按钮为 pill 圆角，选择器为 `12px` 圆角并使用 DS input shadow。数据迁移选择器宽 `112px / 80px`，备份频率宽 `96px`，清理范围宽 `112px`；开关固定 `34 × 20px`、滑块 `14px`。
4. 数据迁移通过 Electron 原生文件选择器执行真实全量 JSON 导出与导入；导出范围可选全部数据或单个工作区，导入支持跳过/覆盖冲突。数据备份通过 SQLite 在线备份生成一致性快照，备份目录和频率偏好持久化在本机。
5. 存储管理按 NewMax 顺序呈现四列实时统计、数据目录、优化存储、清理空附件目录、清理范围和清空对话历史，随后以独立卡片呈现清空本机数据。优化、空目录清理和对话清理均调用 Runtime；云同步和删除全部本机数据只有在对应后端合同完整时才能启用。
6. 数据文件只经用户主动选择的本机路径读写；API Key 和 SecureStore 内容不进入全量导出，导入前校验格式版本并在事务中应用，失败不得留下部分写入。

### 5.4 设置连接页

1. “连接”页以参考客户端的连接设置为视觉与排版基准：顶部为连接器、MCP、插件、搜索服务、机器人对话、开放网关和网络七段滑动轨道，其下是 SYNC-THINK Provider / 第三方 Provider 切换条；正文保持独立滚动，底栏固定。
2. SYNC-THINK Provider 目录固定为三列、每列九项，名称、顺序、`28px` 本地图标和行高必须稳定。不显示没有结算后端支撑的余额或按量计费文案；目录摘要明确动作数量以真实 MCP 工具发现结果为准。
3. 点击托管连接器先进入能力详情：头部展示图标、启用状态和启停命令；动作区只呈现实际注册服务的 `tools`，包含搜索、刷新和空态。未配置连接器只有在详情页点击“启用连接器”后才打开居中配置弹窗，保存 Endpoint/鉴权并发现工具，不得首次点击就跳入通用表单。
4. 第三方 Provider 与 MCP 页继续展示真实已注册服务，并提供新增、编辑、启停、删除和刷新工具目录；托管详情与第三方编辑不得共用同一首屏交互。
5. “机器人对话”使用双栏布局：左侧按 NewMax 1.1.15 的顺序展示 Telegram、飞书、企业微信、微信、Discord、钉钉和 QQ，并使用随应用打包的本地平台图标；右侧呈现所选通道的实时状态、平台专属配置、测试/保存和启停。七个平台均接入真实 Runtime 网关，不显示静态成功状态或不可操作占位。
6. Token、App Secret、Secret 和 Client Secret 只通过 IPC 进入 Runtime 并保存到 SecureStore；Renderer 只读取 `credentialsConfigured`、公开应用 ID、Bot 身份、连接状态和脱敏错误。测试并保存执行平台真实鉴权，启用后 Runtime 持有长连接或长轮询；微信按 iLink/ClawBot 协议在原位弹层扫码并轮询确认，确认后的 Bot Token 不返回 Renderer。切换、弹层与状态使用短位移/透明度动画，`prefers-reduced-motion` 下静止。
7. 插件页复用真实插件配置，开放网关页保留真实启停、监听端口和请求日志。搜索服务与网络在尚无产品合同期间使用明确空态。

### 5.5 设置模型页 · 图像生成

1. 「图像生成」以 NewMax 1.1.15 的生图供应商双栏为视觉与文案基准：左侧「生图供应商」「拖拽排序，首位为默认」，首位标记「默认生图」，底部「+ 添加生图模型」。不要加入 NewMax Gateway。

3. 目录与实际调用走本仓库已有的 `openai-images`（OpenAI Images `POST /v1/images/generations`）。生图接口下拉展示 NewMax 的五项名称，但 Grok OAuth、Gemini Imagen、DashScope 异步适配不在当前页实现。图像专用供应商不出现在「文本生成」列表和聊天模型菜单。
4. 生图接口选择存在 `image-generation` 设置里，不得写入 API Key。密钥仍走剪贴板 hop + SecureStore。

Locked 布局规则：

1. 左导航从项目开始，任务嵌套在所属项目下；本地文件夹是项目的可选单一绑定，不是项目本身。
2. 中心是完整可滚动对话历史。
3. 默认用户右 / Agent 左；可切换单栏阅读。
4. 右侧任务 / Run 信息栏默认可视、可折叠；默认显示任务进度，Trace/Manifest 在执行详情中按需打开；折叠不暂停 Run。
5. 对话是唯一主表面；复杂任务在对话内自动升级并出现可审批计划，可进图视图。

产品态密度规则：

1. 开发期 readiness/规格自检投影不得在产品首屏重复占位；保留纯投影与测试，通过按需验证工作台查看。
2. M1/M2 已完成后，**M1 验证**工作台退出普通产品界面；纯投影、测试与历史证据继续保留在仓库中。
3. 里程碑验证信息只在开发诊断入口按需出现，不得把完整对话与 Compose 挤出窗口。
4. 左栏以带文字的产品导航常驻：项目、智能体、模型源、审批；项目区显示项目/任务树，并把目录绑定作为项目次级属性。记忆作为次级入口，工具详情使用单层临时抽屉。项目树、导航和 Runtime 状态不得与工具详情同时竞争窄栏高度。
5. 左栏只有任务树是弹性滚动区；工具抽屉正文拥有独立滚动。禁止左栏外层、任务树和详情形成三重滚动条。

创意布局加分项（鼓励）：

- Context Continuum 不只是细条，而像“证据时间带”
- 计划块像可签署的执行契约，而不是普通 checklist
- 轨迹项像显影事件，而不是日志刷屏
- 多 Agent 并行时用泳道/丝带暗示，而不是只改头像颜色

### 6.1 使用统计与缓存用量

使用统计是面向技术用户的高密度核对表面，目标是快速比较请求、Token 和费用，不采用装饰性卡片或长期展开的详情列。

1. 顶部摘要固定为总请求、总费用、总 Token、缓存命中率。缓存创建量只作为 Token 拆分明细，不作为成功指标。
2. 请求表分列显示时间、供应商、模型、Token、费用、延迟、状态。Token 列只显示总数，悬停空心圆查看明细；费用列只显示总额，不提供圆标或逐行展开。
3. Token 明细顺序为：输入 Token → 输出 Token → 缓存读取 → 缓存创建 → 总 Token。仅当该请求上报了对应缓存字段才渲染该行；已上报的 `0` 如实显示，未上报则整行不出现，不写「未上报」。
4. 请求表不提供左侧 Chevron，也不展开请求信息 / Token / 费用明细区；不提供会同时撑开所有行的全局「详情记录」复选框。
5. 请求表最小宽度为 720px，常规行高 40px；行悬停对整行使用同一背景，Token/费用单元格不得另叠一层遮罩。空心圆悬停只加深边框、保持透明填充。
6. 命中率使用既有 continuum/success 强调色；普通数字保持中性色，不为缓存读写新增独立彩虹色系。
7. Provider 返回的 `cache_write_tokens=0` 必须如实显示。若后续请求已有缓存读取，创建 0 仍可能只是中转未上报写入量，界面不得自行推算或伪造创建 Token。

## 7. 交互状态

```text
loading：流式字/轨迹脉冲/Continuum 微位移；避免整页转圈
empty：讲清“这里将来是什么”+ 一个主行动
error：分类、可行动、可打开脱敏诊断；视觉上严肃但不恐吓
success：完成印记进入轨迹与 Continuum；克制，不放烟花
disabled：灰显 + 原因
hover/focus/active：focus 必须可见；hover 可有 1–2px 层级变化，但不抖布局
表单校验：即时、局部、可恢复
危险确认：重操作有确认层与后果摘要
权限不足：说明策略拦截来源
网络异常：可重试/可切换回退策略（若用户已配置）
```

### 7.1 动效语法（可感知，但有目的）

产品设计要求动效解释状态；用户要求可获奖级感知力。本项目取 **“可明确感知的功能性动效”**：

| 场景                   | 期望感知                   | 时长指引                        |
| ---------------------- | -------------------------- | ------------------------------- |
| 打开/折叠轨迹          | 空间呼吸，中栏扩展         | 200–300ms                       |
| Agent 交接             | 上下文从 A 到 B 的路径     | 250–400ms                       |
| Context 写入 Continuum | 证据带被点亮/接入          | 180–280ms                       |
| 计划待批准             | 轻微但明确的等待态         | 循环须可关，reduced-motion 静态 |
| 产物生成               | 新版本落入版本架           | 220–320ms                       |
| 对话升级为协作计划     | 计划区域进入并同步任务状态 | 150–220ms                       |

规则：

- 普通 UI 过渡 150–300ms；关键叙事时刻可到 400ms
- **要能被普通用户感觉到**，但禁止环境装饰循环动画
- 禁止渐变光球、bokeh、无意义 partial-screen shimmer
- 尊重 `prefers-reduced-motion`：改为瞬时状态切换 + 静态指示
- 动效服务理解；任何“好看但无信息”的动画删掉

## 8. 需要避免的问题

```text
不适合：营销落地页、赛博霓虹、模板 SaaS 后台、通用 ChatGPT 换皮
不应：深浅分裂主题；轨迹不可折叠；把每个区块做成大圆角阴影卡
不应：Agent 色当唯一状态；无信息装饰；两侧空洞窄内容
不应：静默换模型；折叠轨迹即停 Run；自动把闲聊写成长记忆
不要：照搬 V3 视觉；只改颜色不改组件；组件库默认皮肤直接上
可访问性：只靠颜色；焦点丢失；对比不足；键盘陷阱
性能：超长对话不虚拟化；轨迹无限 DOM；重型预览进主包
质量失败标准：
  - “看起来像又一个 AI 客户端”
  - “很花但不知道系统状态”
  - “很干净但没有记忆点”
```

### 12.1 新人工作区覆盖规则（2026-07-16）

权威规格：`docs/superpowers/specs/2026-07-16-beginner-desktop-workspace-design.md`。

1. Context 结构槽继续存在，但普通产品表面用任务面包屑、负责人、模型和一个 `下一步` 表达，不展示脚手架分类或任务版本。
2. 右栏继续承担 Run 检视且可折叠，但默认视图是用户可理解的任务进度；Manifest、Trace、执行图与版本工具进入 `执行详情`。
3. 健康对话不显示 Runtime readiness 卡；断线/失败仅显示一条紧凑可恢复提示。
4. 全新用户空态只显示三步主路径，不显示 Runtime、Run、消息数、模型数和跨 Provider 检查清单。
5. Agent、模型源和审批入口必须持续显示文字；图标只辅助识别，不承担唯一含义。
6. 右栏折叠到 44px 时只保留居中的展开图标；标题、快捷键提示和折叠说明不得在窄轨内显示或逐字换行。
7. 同一任务状态只能出现一个主协作 CTA；右栏可呈现进度和下一步摘要，但不得复制中心主操作。

### 12.2 项目与文件夹绑定交互（2026-07-16 用户确认）

1. 产品表面统一使用“项目”，内部 `Workspace` 名称仅保留在代码和协议中。
2. 空态标题为“还没有项目”，主操作为“新建项目”，不得要求用户先选文件夹。
3. 新建项目使用产品内表单，明确展示名称、校验、提交中和失败状态；禁止依赖 `window.prompt`。
4. 未绑定项目只显示文件夹绑定图标操作；点击后调用系统目录选择器并持久化绑定，不常驻额外状态行。
5. 已绑定项目不常驻显示目录 basename；项目 hover/focus tooltip 显示完整路径，项目下继续提供“新建任务”。
6. 目录选择取消不产生错误；重复目录、非法路径和 Runtime 失败必须在项目区给出可见错误。
7. 项目创建、目录绑定和任务创建不得互相隐式触发。

### 12.3 对话优先工作区覆盖规则（2026-07-16）

1. 项目树不常驻显示绑定目录 basename；项目 hover/focus tooltip 显示完整规范路径。
2. Compose 工具栏承担项目、Agent、模型三个可操作上下文入口，项目切换优先恢复目标项目最近任务。
3. 新任务即时创建且不弹出命名表单；首次用户消息持久化后自动生成简短标题，完整首条需求成为任务目标。
4. 任务头不重复显示当前队友、模型或参与模式分段控件，只保留项目/任务、状态和显示控制。
5. 对话页面始终不变。显式多 Agent 请求或高复杂度端到端请求自动进入协作状态，并在消息流中生成可编辑、需审批的计划。
6. 自动升级只使用已配置的 AgentVersion 及其模型绑定；不得静默选择未配置模型，计划批准前不得执行。

### 12.4 递归 Pane 与文件编辑规则（2026-07-28）

1. 默认仍以单 Pane 完整对话为主表面；用户显式分屏后才进入递归横/纵布局，每个 Pane 自己管理对话与文件 Tab。
2. 分隔比例固定在 20%–80% 可用区间；拖动与键盘调整不得造成内容重叠，Pane 焦点必须可见并决定新建、打开和右栏归属。
3. 分屏、关闭 Pane、保存等工具操作使用 Lucide 图标与 tooltip；Tab 的关闭按钮、未保存标记和图标槽使用稳定尺寸，状态变化不得推动标签文字跳动。
4. 文件 Tab 以小圆点和编辑器状态文字共同表示未保存，不能只靠颜色；保存按钮支持 `Ctrl+S`，脏文件或包含脏文件的 Pane 关闭前必须应用内确认。
5. 干净文件外部变化自动刷新；本地已有草稿时显示单层冲突条，只提供“加载磁盘版本 / 覆盖磁盘版本”两个明确动作，不在卡片内再套卡片。
6. Workspace 快照只恢复 Pane、比例、焦点和资源 Tab；文件正文、未保存草稿、loading/error 与流式状态不持久化。切换 Workspace 可保留当前应用会话内的草稿，应用重启后重新读取磁盘。
7. 当前轻量工作区文件编辑器继续复用 `<textarea>` 与既有 tokens；文件编辑若引入 CodeMirror/Monaco 等重型依赖，仍需单独技术选型门禁，不随 P0 默认进入首屏包。
8. 对话行右侧只保留“打开工作区文件”这一项 Pane 操作；“工作区文件”作为资源 Tab 展示，但不进入 `+` 新建菜单，旧的“打开右栏”按钮不再占用对话行末端。

### 12.5 内容搜索与终端 Pane 规则（2026-07-28）

1. 文件 Dock 使用“文件名 / 内容”分段控件切换搜索对象；内容结果优先显示相对路径、行列和单行预览，不用装饰卡片稀释扫描密度。
2. 搜索 loading、empty、error、truncated 和 timed-out 状态必须就地可见；新查询替代旧查询时不闪回过期结果，点击命中后由焦点 Pane 打开并定位。
3. terminal 与 conversation/file 使用同一 Tab 语法；终端图标、关闭按钮和状态槽尺寸固定，标题过长使用省略号，不挤压 Pane 工具按钮。
4. 终端内部固定为 34px 状态头、可伸缩 xterm 输出和 39px 命令栏；三者边界相接但不重叠，运行/停止切换不得改变命令栏高度。
5. cwd、就绪/运行/错误状态和清空操作放在状态头；命令栏只承担提示符、输入和运行/停止。清空必须重置真实 xterm 画布，不只清空 React 文本状态。
6. xterm JS/CSS 只在 terminal Tab 挂载时加载；浅深主题切换必须同步 xterm palette，viewport 背景与 Pane 背景一致，避免出现独立黑块或白块。
7. Workspace/应用恢复只承诺 terminal Tab 和相对 cwd；历史输出、运行状态和输入不进入布局偏好。恢复后的空终端明确显示“就绪”，不得伪装旧命令仍在运行。
8. 当前产品表面是受控命令终端，不展示持久 shell、交互 stdin 或会话续接暗示；需要 PTY 时单独设计权限、恢复、打包和视觉状态。

### 12.6 每轮 Skill 选择规则（2026-07-29，2026-08-31 取消每轮 8 项上限）

1. Skill 入口位于 Composer 左侧工具组，使用 Puzzle 图标；未选择时只显示图标，选择后只显示已选数量。打开、选中和发送状态不得改变 Compose 行高或推动相邻控件。
2. 菜单列出当前工作区已启用且可选用的 SkillVersion。Agent/Team 对话仍默认带上有效 owner 已装备的版本；模型直聊可从工作区目录勾选。
3. Skill 目录只在菜单首次打开时请求 metadata；必须覆盖 loading、error/retry、empty 和成功状态。Renderer 不为了展示列表读取完整 `SKILL.md` 正文。
4. 菜单支持多选、逐项勾选、版本号、单行说明和一键清空。没有每轮 8 项产品上限；勾选数量与 NewMax 一样只受目录规模和协议载荷边界约束，不得因选中项变多而让菜单尺寸跳变。
5. Agent/Team 对话默认选中有效 owner 已配置的 Skill；配置入口仍在 Agent Library，Composer 只用于当前会话的临时取消或调整，不要求每条消息重新勾选。
6. 发送成功和失败都保持当前选择；切换 Agent/Team 时重置为新 owner 的默认配置，切换到模型时清空本轮勾选。只切换模型 override 不清除 Agent Skill。
7. 欢迎页首条消息与普通对话使用同一规则；首条消息的临时覆盖必须延续到新打开的对话，不能在创建完成时突然恢复全选。
8. 弹层优先放在触发器上方，受视口碰撞约束；浅色 1440x900 和深色 1280x720 均不得出现页面溢出、文字截断或与 Composer 命令区混叠。
9. 选择 Skill 不表示执行脚本或增加工具/MCP 权限；界面不得暗示自动推荐、项目临时附件或市场能力已经交付。
10. 目录 metadata 等价刷新不得覆盖当前会话的临时选择；有效 owner ID 变化必须恢复新 owner 默认值，即使新旧 owner 恰好装备相同 SkillVersion ID。

### 12.7 Browser Automation Studio 与 Profile 会话规则（2026-08-05）

1. Browser 页面使用左侧窄 Profile 列与右侧工作区，不在 Profile 项内嵌套统计卡；Profile 行只显示名称、站点数、最近使用和当前选择状态。
2. 右侧首层使用“自动化任务 / 登录状态 / 录制记录”分段视图，并默认进入“自动化任务”；任务列表是真实 Runtime/SQLite 投影，不使用假按钮或说明卡冒充未交付能力。
3. 站点会话使用可扫描列表：favicon/域名、状态、最近检查、关联任务数和行尾菜单。状态颜色只作辅助，必须同时有中文文本。
4. “已验证登录”与“存在会话数据”必须视觉和文字区分；任何缓存摘要均显示最近检查时间，不把 Cookie 存在误写为账号在线。
5. 刷新为明确命令，会在需要时打开专用系统浏览器；按钮保持固定尺寸并在执行中使用旋转 Refresh 图标，不改变工具栏高度。
6. 清除站点会话使用单层确认 Dialog，列出主站/子域、将删除的数据类型、受影响 Workflow 和默认保留的第三方 SSO；危险按钮使用 error token，不使用连续二次点击暗示确认。
7. Profile 正被 Run/handoff/lease 使用时，删除和清除按钮禁用并显示具体占用原因；不得吞掉错误或只在 DevTools 输出。
8. 空态、缓存态、刷新中、刷新失败、清除成功和 Profile 删除失败均在原区域就地表达；不使用装饰插画、卡片套卡片或大段功能教学文案。
9. 录制栏使用可选 HTTP(S) 起始网址、主命令按钮、最近录制选择器、状态和固定 `0/200` 计数；开始/停止切换不得改变工具栏高度。
10. 录制步骤使用紧凑表格展示序号、动作、脱敏目标和时间。敏感输入固定显示“敏感值，运行时填写”，URL 不显示 query、hash 或 userinfo。
11. start 请求发出后立即锁定全部 Profile 切换与维护；请求超时后必须向 Runtime 对账。只有明确确认无活动录制才解除锁，未知结果保持 fail-closed。
12. `failed/interrupted` 必须显示具体终止原因并清理过期成功提示；用户关闭系统浏览器 Page 后，界面轮询到终态并立即恢复 Profile 可维护状态。
13. 自动化任务列表采用紧凑表格表达任务名称、目标、来源、状态和单一主操作；搜索、刷新、手动创建和“让 AI 创建”位于固定工具区，空态直接提供两种创建入口。
14. Task Draft 进入录制工作区后，顶部持续显示任务名称与来源；只有当前 Draft 对应的已停止录制可提交审核，禁止把任意历史录制误关联到 Task。
15. 审核 Dialog 展示脱敏步骤、来源、起始站点和状态。驳回按钮明确写“驳回重录”，批准按钮明确写“批准并发布”；敏感输入固定显示“敏感值，运行时填写”。
16. 已批准任务显示不可变 `Vn`，并明确提示发布版本不会被后续编辑覆盖；当前切片不展示“运行”“定时”等尚未接入确定性执行器的操作。
17. 专用系统浏览器默认优先 Chrome、Edge 回退。录制 Page 右下角显示最小宽度 260px、距边缘 18px 的 Shadow DOM 浮层，包含红色状态点、`MM:SS · N 步` 与“结束录制”；点击浮层不得生成录制步骤。
18. AI 创建入口与对话 `browser_workflow_create_draft` 都只生成 AI 来源 Draft。普通工具审批受 execution mode 控制，但“批准并发布”始终保留为用户在任务页执行的人类审核动作。
19. Task 标题始终打开详情；行尾只保留一个状态相关主操作：草稿“继续录制”、待审“审核”、已发布“录制新版本”。创建新版本后返回列表必须显示“新版本草稿”，不得继续缓存旧 `enabled/V1` 状态并重复创建 Draft。
20. V2 编辑或审核期间，详情以当前 Draft 为主，同时单独标明仍生效的旧 `Vn`。待审步骤不得回退显示旧发布版本；批准前旧版本保持不可变，批准后才切换指针。
21. 审核历史使用紧凑列表显示批准/驳回、备注与时间；兼容旧 Runtime 缺少历史字段的响应。最多显示最近 100 条时必须显示截断提示，不静默丢弃记录。
22. 自动化搜索同时覆盖任务名称、目标说明和网址。有关联 Task 的 Profile 删除失败时关闭确认框并在原区域解释保留原因；任务重绑/归档交付前不得暗示用户可强制删除。

### 12.8 对话执行过程与运行态规则（2026-08-07）

1. 每轮助手执行过程只使用一个顶层披露入口，标题固定为“执行过程 · 耗时”，默认折叠；开始 streaming、结束 streaming 或工具状态变化均不得擅自覆盖用户的手动展开选择。
2. 耗时使用自然中文紧凑格式：不足一分钟显示秒，超过一分钟显示分秒，超过一小时显示时分秒；不使用固定宽度数字时钟制造系统监控感。
3. 普通执行 UI 的唯一文字真源是 assistant `commentary`，不得把 Provider reasoning、reasoning summary 或内部诊断文本提升为“思考过程”。Commentary 与工具调用必须按真实 sequence 混合呈现为统一时间线：先显示动作前的 commentary，再显示对应工具调用及结果，然后继续后续 commentary 与动作；不得将全部工具和全部 commentary 分别集中展示。
4. 同一段 commentary 之后、下一段 commentary 之前的连续工具调用统一归入一个默认折叠区块，标题为“调用了 N 个工具”；展开后显示该组全部工具。每个工具仍保留独立折叠按钮与 Chevron，可分别查看 Path、Command、URL、Output 和退出码，工具结果不得脱离对应工具卡。执行步骤不显示时间点；顶层整体耗时可以保留。
5. 流式内容默认跟随执行过程尾部；用户向上滚动即暂停跟随，回到底部后恢复，避免新 Token 把用户正在阅读的历史内容拉走。
6. 任务“正在运行”状态必须以 Runtime 当前活动 Run 集合为权威真源。历史 `run.started` 只有在当前 Runtime 仍报告相同 Run ID 时才可保持活动；重启或重连后的孤儿开始事件不得让任务永久转圈。
7. Provider 同模型重试与 fallback 切换必须在当前助手轮次内显示短暂状态，分别使用“正在重新连接 N/M”和“正在切换备用模型：A → B”；收到该 Run 的新 commentary、final text、工具进展或终态后立即撤下，不保留为历史消息。
8. 执行过程的自动跟随只能被明确的用户上滚暂停。内容增长、浏览器布局调整或程序化滚到底部产生的 `scroll` 事件不得误判为阅读意图；用户回到底部或重新展开活动过程后恢复跟随。
9. Markdown fenced code/text 块只有在实际提供展开控制时才允许使用折叠高度和裁切。短块必须按完整内容自然撑开，不能出现“内容被截断但没有展开入口”的死路。
10. Provider reasoning 与 reasoning summary 只用于诊断、导出、兼容恢复和 Provider 上下文连续性；普通聊天消息筛选、执行过程渲染、自动滚动锚点和空消息判断均不得依赖 reasoning 是否存在。
11. Provider 未返回 commentary 时只显示真实工具步骤，不生成或补写虚假的执行说明。Commentary 按 Markdown 正文渲染，保留段落、强调、列表和行内代码；跨帧增量原样拼接，Runtime 仅在工具边界处关闭当前 segment，并在后续 commentary 到达时建立新 segment。
12. reconnect/fallback 必须延续同一用户可见 assistant turn：已经显示的 commentary 不消失、不重复；失败模型的未完成 final answer、reasoning 和未完成工具不得继承到备用模型；备用模型的新 commentary 从新的 segment 开始。
13. 对缺少原生 phase metadata 的流式文本，以 §12.17 规则 18 为准：未分类 `draft.text` 后缀必须在当前顺序位置流式出现。旧版“暂存到边界再整段显示”已废止，因为它会让说明正文弹出来。

### 12.9 流式回复、上下文统计与连接状态规则（2026-08-08）

1. Provider delta 到达 Renderer 后必须以逐帧增长方式呈现，不得因为事件已进入内存队列就一次性同步清空。单帧消费需要有稳定上限，工具调用、Terminal 输出和终态事件必须在它们之前的文字帧已消费后再呈现。
2. 每个助手轮次在完成后显示本轮耗时、模型和 Token。统计归属以 Provider 请求为边界，同一请求的渐进 usage 只保留各字段最大值；一次助手轮次包含多个 Provider 请求时汇总这些请求，而不是只取最后一次。
3. “当前上下文占用”与“会话累计消耗”是独立指标：前者仅表示最近一次模型请求的输入上下文，后者累计当前任务全部 Provider 请求的输入与输出。两者不得相加、互相覆盖，也不得混入其他 Task/Thread 的 usage。
4. 上下文环的悬浮说明必须同时给出当前占用、上下文上限、剩余量、分区与会话累计，并为精确 Token 值提供可访问的 `title`，避免只依赖百分比和四舍五入后的短数字。
5. Runtime 正在重连时显示当前尝试次数；连接失败时显示可识别的失败原因；同模型重试和 fallback 切换继续使用 Run 事件作为真源。状态优先附着于活跃助手轮次，没有活跃轮次时使用独立 `role="status"`，连接恢复后及时清除。
6. 历史 usage 缺少直接 Task/Thread 字段时，只允许通过可验证的 Run/Thread 关系回溯归属。完全无法归属的旧事件不得为了“统计完整”而默认计入当前会话。
7. 长对话使用覆盖在消息视口左侧的消息导航轨道，不创建第二条滚动条（2026-09-05 确认保留左侧）。每轮问答保留一个刻度，整组垂直居中、间距随数量自适应，不因回答高度变化而拉开。刻度默认中性色，当前项更长更亮，不使用光晕；透明轨道的命中宽度为 32px，在刻度组及上下 16px 缓冲内连续匹配最近刻度，外围空白不截获消息操作。导航来自已加载消息，完整历史索引另行设计，不将局部索引假装成完整会话目录。
8. 导航 hover/键盘 focus 只预览、不滚动。预览卡向右展开，最大 280px 且受聊天列宽度约束；用户问题为主标题，回答为次级摘要，各最多两行，时间弱化。回复进行中只显示简短执行状态，不堆叠正文或 commentary；无答案时不拿思考代替。点击优先定位到本轮首条用户消息，问题尚未加载时回退到助手回答；保持 content-visibility 预热与定位校正，暂停自动贴底直到用户明确回到最新。当前阅读项按问题锚点所在轮次判断，不提前高亮下一轮。保留 nav、含轮次/问题的按钮标签、aria-current、关联预览的 aria-describedby 和可见键盘焦点；Escape 关闭预览，reduced-motion 移除动效。

### 12.10 执行中待处理需求与插话规则（2026-08-08）

1. 当前 Conversation 存在活动 Run 时，Composer 仍允许输入。常规发送动作只创建“待处理需求”草稿，并在输入框上方展示；不得直接创建正式 user message 或抢占当前 Run。
2. 待处理需求必须按 Conversation 隔离并按创建顺序排列。正文、附件、推理档位、联网状态和 Skill 版本使用入队快照；模型在正式派发时读取当前界面选择，确保用户先切换模型、再插话或等待自动派发时，界面选择与实际请求模型一致。切换对话或重启 Renderer 后应从版本化本地存储恢复。
3. 草稿尚未正式派发时不属于任务上下文：不写入 Message/Event，不传给 Provider，不参与上下文占用、缓存命中或 Token 消耗。编辑和删除仅修改 Renderer 草稿。
4. 当前 Run terminal 且 durable history 已可恢复后，队列按 FIFO 自动派发队首。草稿转为正式 user message 后启动新 Run，新 Run 使用此前完整持久上下文；派发成功后才从队列移除。自动派发只能发生在当前 Run 已确认不活跃之后，禁止用延时兜底在仍在执行的回复上抢发下一条。
5. 每条草稿提供“插话”按钮。只有用户主动点击时才立即派发，并由 Runtime 以 `superseded-by-new-message` 终止同 Thread 的旧 Run。旧 Run 已产生的 commentary、工具结果和部分 final answer 按 cancelled 状态持久化，新用户消息随后进入正式上下文。
6. cancelled assistant 内容恢复给下一轮 Provider 前必须插入明确的中止边界，表明后续内容只是上一轮中止前的部分输出；不得把残缺 final answer 当作完整答复继续推理。
7. 自动派发失败必须保留草稿并停止自动重试；用户可编辑、删除或手动重试。发送中的草稿禁止重复编辑和删除，其他未派发草稿保持可操作。
8. 派发锁、失败状态和异步结果必须按 Conversation 隔离。重连、切换对话再返回或后台发送结束均不得重复派发，也不得覆盖当前对话的 `threadId`、乐观消息、标题、错误、压缩提示或焦点。
9. 待处理区在桌面端使用紧凑单行操作布局；窄屏下操作区换到正文下方。所有编辑、删除、插话、保存和取消控件必须提供可访问名称、键盘焦点反馈和明确的发送中/失败状态。
10. 上下文入口标题固定为“当前上下文窗口”，其占用值与容量按当前选中模型重新查询；“会话累计 Token”只累计当前 Task/Thread 内已上报的 Provider usage。没有 usage 事件时显示“尚未上报”，不得使用伪造的 `0`。
11. Durable `run.completed`、`run.failed`、`run.cancelled`、`run.paused` 是执行终态真源，必须覆盖可能滞后的 `process.running` 快照。终态到达后停止活动动画、冻结耗时，并同步归并仍处于 running 的工具步骤。
12. Composer 的权限、推理强度和模型菜单必须区分 hover、展开和选中状态；选中项的文字、图标、背景、边框与勾选使用同一强调层级，同时保证中性展开态不会覆盖已有的权限强调色。

### 12.11 资源库、新会话与模型目录规则（2026-08-08）

1. 智能体与小队的列表页共用同一套资源库视觉语法：页面边界、标题栏、卡片网格、描述高度、元信息区和底部操作必须对齐；hover 与 selected 使用中性主题层，强调色只用于主操作、身份图标和明确勾选。
2. 智能体详情与小队详情共用同一 Dialog surface、遮罩、头部、滚动正文和底部动作区。详情页字段结构可以不同，但背景、边框、圆角、间距、焦点和窄窗口单列规则不得分叉。
3. 资源卡片缺少描述时使用稳定占位文案保持高度，不因某一条数据缺失导致同一行卡片底部操作错位；鼠标操作出现时不得推动卡片正文重新排版。
4. 点击“新建对话”后，临时会话立即作为普通列表行插入当前全部会话中，历史会话继续可见且可切换；不得进入隐藏其他会话的独占空态。
5. 同一 Pane 重复点击“新建对话”复用现有临时会话。临时会话在首轮请求成功建立正式 Task 后原位替换为正式 ID、保持当前 Tab 与列表位置；首轮前关闭只移除本地临时项，不调用 Runtime 删除。
6. 设置 Dialog 的定位值使用整数像素，入场动画结束后必须回到 `transform: none`；正文不允许长期驻留在缩放或小数位移合成层中，以避免 Windows/Electron 下中文字体发虚。
7. “添加模型”先进入服务商目录，不直接暴露空白配置表单。目录至少包含“推荐服务、国内服务、聚合平台、海外平台、本地模型”，并同时提供“自定义供应商”和“从 CC Switch 导入”。
8. 服务商目录使用可扫描的两列卡片，窄窗口降为单列。卡片展示名称、用途说明、协议或分类信息；selected、hover、推荐标签和主按钮分别使用中性 active、hover、小面积 accent 与实色 accent，不使用整卡高饱和背景。
9. 选择服务商模板后进入可编辑配置页，并预填已确认的名称、Base URL、协议和本地模型标识；“返回服务商目录”保留当前分类，“取消添加模型”恢复进入流程前选中的 Provider。
10. CC Switch 导入必须先读取本机数据库并展示可导入项、Base URL、模型数量、模型标识、密钥状态与 warning；支持全选和逐项选择。导入成功后刷新 Provider 列表并定位到首个成功项，部分失败通过结果摘要明确呈现。

### 12.12 Skill 管理与 MCP 能力规则（2026-08-26 NewMax 1.1.14 实机对齐）

1. Skill 管理使用独立的 NewMax 信息架构，不再显示“Skill / MCP”顶层分段开关，也不再显示第三个“本地”页签。页面固定为 52px 标题栏（返回、`Skill 管理`、`Skill 激活码`、`创建 Skill`）和“Skill 市场 / 我的 Skill”两项次级页签；MCP 保留独立管理面并通过产品导航进入。
2. 列表名称必须来自持久化记录中的正式显示名称，不从目录 slug、ID 或安装路径反推。Skill 正文与源码使用清晰的等宽字体、正常字重和不小于 13px 的字号；标签、筛选项和 MCP 元数据不得使用低对比度或缩放产生的模糊文字。
3. Skill 每行呈现健康状态、来源、激活工作区、最近 45 天调用次数、最后调用时间和全局启用开关；MCP 每项呈现品牌或站点图标、连接状态、Transport/Endpoint、工具数量、最近调用情况和全局启用开关，不显示工作区激活。图标按名称/Endpoint 识别（GitHub、Context7、文件系统等），远程 HTTP 回退到站点 favicon。成功、失败、取消均计入调用次数；失败、无工具、未信任或启动命令仍是未展开的环境变量时计入“需检查”。MCP 可调用条件是全局启用 ∩ 已发现工具 ∩ 启动命令可解析；仅登记或 Agent 未绑定仍不能 dispatch。
4. Skill 实际生效集合固定为“全局启用 ∩ 当前工作区激活 ∩ Agent 绑定”。MCP 按 TD-041 使用“全局启用 ∩ Agent 绑定”，历史 MCP 工作区激活记录仅保留审计、不参与有效集合。全局停用只暂时阻断调用，不删除既有关系；重新启用后原关系自动恢复。
5. Compose 输入 `/` 时只列出当前有效 Agent/Team owner 绑定、全局启用且在当前工作区激活的 Skill。停用或未激活 Skill不进入菜单；选择 Skill 遵守当前轮临时覆盖规则，没有每轮 8 项上限。
6. MCP 工具目录和实际 dispatch 必须同时满足全局启用与 Agent `mcpServerIds` 绑定；注册本身不授予任意 Agent 使用权限。MCP 列表需要明确显示连接状态、Transport/Endpoint、工具数量和最近调用情况。
7. 「我的 Skill」常驻上下文占用按 NewMax skill xray 统计：只加总已纳入目录的 Skill frontmatter `description` 字符，不是完整 `SKILL.md`，也不是历史运行注入 Token。建议上限 15,000 字符。全局范围汇总全部全局启用项；切到某工作区后只汇总「全局启用 ∩ 该工作区已激活」。`description` 为空记为缺描述，超过 1,536 字符记为描述截断；行内「已扫描」表示这两项健康检查都通过。MCP 工具目录占用仍按当前 Agent 绑定且全局启用后注入 Provider 的工具名称、描述和 Input Schema 计算。未读取的 references/scripts/assets 不计入。详情抽屉里的历史 Token 只表示实际进入过 Context Packet 的用量，不驱动顶栏常驻占用。
8. 历史已安装 Skill/MCP 迁移后默认全局启用；新建、导入或注册的本地能力也默认启用。Skill 仍需工作区激活和 Agent 绑定才可实际调用，MCP 只需 Agent 绑定。
9. “创建 Skill”下拉菜单严格只有“导入 / 创建 Skill”两项。市场 Skill 编辑时创建本地派生版本并保留来源关系，不覆盖市场原版；本地 Skill 创建必须生成真实可用的 SkillVersion。
10. “发布到市场”从 Skill 详情管理面进入，当前只保存本地草稿，可编辑和继续保存；提交时明确显示“市场发布渠道暂未开放”，不得伪造审核中或已提交状态。
11. “一键整理”只生成可检查报告，列出未使用、未激活、有问题和高上下文占用能力，不自动删除、停用或改变绑定。
12. 保留“Skill 激活码”入口。当前点击后以现有主题样式显示“筹备中”，不创建虚假兑换、授权或联网流程。
13. hover、focus、selected、disabled 与开关状态必须使用项目现有 surface/border/accent/error tokens；参考界面只锁定结构与交互，不照搬纯黑背景或荧光绿色。
14. 能力中心页面、Radix Portal 弹窗、详情抽屉和遮罩必须共享 Shell 的 `page/surface/elevated/border/text/accent` 语义变量；浅色和深色主题均不得继续使用独立的浅绿色能力页色阶。Portal 内容必须显式继承同一能力变量作用域。
15. Skill/MCP 详情抽屉使用稳定的 header、独立滚动正文和常驻 footer。标题、说明、状态、连接信息、工具清单与操作区分层清晰；按钮在常态、hover、disabled 和窄窗口换行时保持完整可见。
16. Skill 编辑弹窗使用整数像素居中且入场结束后 `transform: none`，避免 Windows/Electron 中文落入长期合成层。名称、版本、描述、`SKILL.md` 与文件导入均有图标和完整字段样式；保存按钮常驻 footer，不依赖 hover 才出现。
17. “导入”使用 NewMax 480px 居中弹窗：顺序固定为文件/文件夹选择、Skill 图标、Skill 名称、Skill 描述和安装位置，footer 固定为取消/导入。支持文件夹、ZIP 和拖放；名称与描述由用户填写，不根据 `SKILL.md` 自动回填。图标支持 Emoji 或本地图片，本地图片裁切压缩为 `128 × 128` JPEG。安装位置为带勾选状态的多选弹层，可同时选择全局与多个工作区；默认选择当前工作区，没有当前工作区时选择全局。名称、描述和图标是独立展示元数据，导入与后续编辑均不得重写实体 `SKILL.md`。
18. AI 自动登记的远端 MCP 在详情抽屉显示“鉴权未配置”与“配置 Key”。配置弹窗预填并锁定名称、Transport 和 Endpoint；已保存 Key 在配置弹窗中通过 uncontrolled input 回填，默认以密码形式显示并支持眼睛按钮切换明文。为满足回显要求，Key 以 App Setting 明文保存并随 MCP 摘要进入 Renderer；能力列表不直接绘制 Key，事件、日志与诊断导出必须继续排除 Key。
19. “我的 Skill”严格按 NewMax 顺序呈现：五区统计、工作区范围、来源/状态筛选与整理/排序、高密度表格。表格列固定为 `SKILL / 安装位置 / 已激活工作区 / 45 天触发 / 最后触发 / 操作 / 启用`；名称行内显示扫描状态、版本和描述，操作固定为使用、编辑展示元数据、共享三个图标。编辑使用 400px 居中弹窗，不进入实体源码编辑流程。
20. Skill 市场目录由 Runtime 通过 `skill.market.list` 提供，Renderer 不把演示卡片作为事实源。作者条目至少包含名称、作者、版本、分类、说明和图标；安装通过 `skill.market.install` 复制完整包目录到 `<home>/.sync-think/skills/<slug>`，必须保留 `references/`、`scripts/`、`assets/` 和模板等附属文件，再登记为市场来源 SkillVersion。
21. 市场安装成功后直接合并 Runtime 返回的 Skill 摘要并更新卡片状态；全局启停使用 Runtime 返回的最新 Skill 就地更新当前行，失败时回滚原状态。两种操作均不得依赖整页刷新才能看到结果。
22. Skill 管理字体栈固定为 Inter Variable、Noto Sans SC Variable 与系统回退，使用浏览器原生抗锯齿和 `text-rendering: auto`。标题、页签和行名称分别使用 `14px / 600`、`13px / 500`、`13px / 600`；说明使用 `12px / 18px`，安装路径使用 `11px / 14px` 等宽字体。五张统计卡等分、单卡高 84px；表格行高 60px；启用开关为 28 × 16px 且不绘制外框。
23. “已激活工作区”单元格使用贴着当前单元格向下展开的菜单，不使用居中 Dialog。触发器高 24px；菜单宽 320px、圆角 18px、内边距 6px，标题与每行分别高 28px / 32px，工作区列表最大高 320px 并独立滚动，底部固定“完成”。菜单中的“全局”表示同步切换当前目录列出的全部工作区，与表格最右侧的 Skill 全局启用开关相互独立；单个工作区仍可分别开关。
24. 全局停用的 Skill 行整体使用 0.55 透明度，并在名称与“已激活工作区”列明确显示“已停用”；工作区菜单和“使用”操作不可触发，最右侧启用开关保持可用。工作区开关使用乐观更新和失败回滚，不重新读取整份 Skill 目录。Compose `/` 查询必须携带当前 Conversation 的 `workspaceId`，Runtime 只返回同时满足全局启用与该工作区激活的 SkillVersion。

### 12.13 多 Pane、标签拖拽与文件工作台规则（2026-08-11）

1. 工作区文件夹标签使用 beUI Morphing Tabs 的指针槽位算法：点击切换时共享的 NewMax SVG 曲面滑到目标槽，拖动时邻签即时让位，松手后提交顺序。对话 Pane 资源标签在条内重排时复用同一 `visualIndexFor` 让位，但仍走原生 `DragEvent/DataTransfer`，以便拖到其他 Pane 开分屏。不引入 `motion` 包，也不改成 beUI 的液态内容面板。键盘可用方向键切换、Alt+方向键排序。鼠标拖拽不得对滚动轨道内的原节点施加无限位移，也不得扩大应用根节点的横向滚动范围。
2. 应用根节点、浮动 Boards、Pane Tree 和每个 Pane 都必须允许子项收缩并截断非所有者溢出；横向滚动只允许出现在标签条、代码区等明确拥有滚动行为的局部区域，页面级 `scrollWidth` 必须等于 `clientWidth`。
3. 同时最多挂载两路实时 `ChatView`，避免重复 transient subscription。第三路及后续活动对话不得渲染空白区域，必须显示可点击、可聚焦的休眠面；点击后换入实时挂载，并保留全部标签和 Pane 布局。
4. Composer 的断点依据所在聊天 Pane 的容器宽度，不依据整个窗口宽度。窄 Pane 下工具栏允许换行，次要文字收起为保留可访问名称的图标，模型名称截断；输入区、上下文按钮和发送按钮始终位于 Pane 边界内。
5. 文件资源在当前 Pane 中以普通文件标签打开。文件标签正文默认同时显示编辑器和嵌入式工作区文件树，编辑器标题栏提供固定尺寸的展开/隐藏按钮；宽 Pane 使用左右并列，宽度不超过 520px 的窄 Pane 改为上下嵌入，两区都必须保持完整宽度和独立滚动，文件树不得覆盖编辑器。
6. 嵌入式文件树对每个文件提供两个稳定动作：点击文件名替换当前文件标签，点击独立的新标签图标保留当前文件并新增文件标签。当前文件存在未保存修改时，替换动作自动退化为新标签打开，避免丢失草稿。
7. 文件名搜索、内容搜索和目录树必须共享上述双打开语义；活动文件高亮、键盘焦点、加载、空态和读取失败均在文件树自身区域表达，不推动编辑器或标签栏重新布局。
8. 隐藏嵌入式工作区文件树后，编辑器必须立即占满文件工作台全部宽高；再次展开时恢复当前 Pane 对应的左右或上下布局，切换过程不得产生页面级横向溢出，也不得遮挡展开/隐藏按钮。
9. 文件工作台容器、代码预览、源码编辑器、文件树搜索区与文件树正文统一使用对话 Pane 的 `--color-chat` 背景语义色，使右侧文件显示区域与左侧对话正文保持一致。编辑器标题栏与同层级的文件/Git 切换栏共享标题背景语义色；局部层级由边框、活动行和控件状态表达，浅色和深色主题均需通过计算样式校验。
10. 文件名只在 Pane 顶部资源标签中显示，文件正文标题栏不得重复绘制路径或文件名。正文标题栏使用固定尺寸的图标分段控件切换“高亮预览 / 源码”，按钮通过 tooltip 和可访问名称解释用途，切换时不得推动状态与右侧操作区位移。
11. 源码模式在右侧操作区提供“复制源码”，复制对象必须是当前完整草稿，包括尚未保存的编辑内容；成功后以勾选图标和“已复制”提供短时反馈，失败时保留可重试状态。复制反馈动画必须遵守 reduced-motion。
12. 高亮预览按文件名和扩展名选择明确的 `highlight.js` grammar；受支持格式显示对应语法色，未知或高亮失败的格式按原始纯文本逐字展示，不得吞掉 `<`、`&` 等内容。
13. 高亮预览和源码编辑器都必须根据可用宽度软换行，长字符串与无空格内容允许在任意字符处折行；行号保持固定窄列，内容区不得要求用户横向滚动才能阅读完整文本。
14. 宽文件工作台中的嵌入式工作区文件树允许通过编辑器与文件树之间的垂直分隔条连续调宽。拖柄使用 Pointer Capture，范围同时满足文件树至少 220px、编辑区至少 280px，并提供方向键、Home、End 和双击复位；窗口失焦、指针取消或布局尺寸变化必须结束当前拖动并恢复光标与文本选择。
15. 文件工作台宽度不超过 520px 时继续使用上下嵌入并隐藏横向调宽拖柄；断点切换前后不得残留拖动状态、固定宽度或页面级横向溢出。
16. `.md` 与 `.markdown` 默认提供排版后的文档预览，保留标题、列表、表格、代码高亮和 Mermaid；源码按钮继续提供完整可编辑文本。文件预览中的 fenced HTML 只能按源码显示，不执行脚本或网络内容。内容搜索命中 Markdown 时自动切到源码并定位精确行列。
17. 未提供专用文档渲染器的文本格式继续使用高亮或纯文本预览；文件类型、读取大小和二进制限制必须通过加载/错误状态如实表达，不得以空白正文暗示预览成功。

### 12.14 执行过程活动阶段自动展开规则（2026-08-14 用户确认）

1. 助手处于可见思考说明或工具执行阶段时，外层“执行过程”默认展开并继续遵守贴底滚动规则；最终回答开始输出或 Run 进入终态后，外层自动折叠为耗时摘要。
2. 相邻且没有思考说明分隔的工具调用属于同一批次。批次中只要仍有任一工具处于 `running`，对应“调用了 N 个工具”分组必须默认展开；该批次全部进入 `done` 或 `error` 后自动折叠。
3. 活动工具批次展开期间，批次内每个单独工具详情也默认展开，包括已经完成但同批仍有其他工具运行的条目；只有整个批次结束后，批次与单工具详情才一起回到折叠态。
4. 工具继续追加到当前相邻批次时必须复用稳定的批次身份，不得因数量或标题变化重挂载组件、丢失展开状态或造成视觉跳动。
5. 自动展开表示默认行为，不得与用户争夺控制权。用户手动展开或折叠外层、批次或单工具详情后，该层在当前 Run 或当前工具批次内保持用户选择；新 Run 或新批次重新启用自动规则。
6. 历史已完成消息默认保持紧凑折叠；用户展开历史过程后，普通重新渲染、计时停止或状态补齐不得再次强制折叠。

### 12.15 模型菜单、思考强度与联网入口规则（2026-08-14 用户确认）

1. Composer 不再把思考强度作为左侧独立按钮。模型菜单底部固定显示“思考强度 + 当前档位 + 右侧箭头”，悬浮、点击或键盘方向键打开同一菜单树中的二级菜单。
2. 模型触发按钮同时显示当前模型名称和思考档位。模型名称允许在窄 Pane 中截断，档位和展开箭头保持完整且不推动发送按钮；按钮的可访问名称必须同时说明模型切换与当前档位。
3. 思考档位为“自动、关闭、低、中、高、超高、最高”，当前项使用稳定宽度的勾选槽位。只有 Provider 提供明确、已确认的档位能力元数据时才允许裁剪；元数据缺失时显示完整档位，不得依据模型名称猜测并隐藏选项。
4. 供应商、模型和思考强度使用同一 Radix 菜单树与主题变量。子菜单优先向右展开，空间不足时自动换侧；hover、click、ArrowRight、Escape、外部点击和焦点反馈均需可用。
5. Composer 左下角不再显示独立联网按钮。“联网搜索”进入 `@` 弹层的“设置”区，使用“开启 / 关闭”分段控制；工作区文件位于独立区域并拥有自己的滚动容器，设置区不得随文件列表滚走。
6. 选择联网状态后移除用于唤起菜单的 `@` token、关闭弹层并把焦点与光标归还输入框。联网状态继续进入原有 `networkEnabled` 请求参数，不创建第二套请求语义。
7. 思考强度与联网状态按 Conversation 持久化并在切换对话或重启后恢复。新建对话首轮使用空态 Composer 的当前选择，Conversation 实体创建后立即写入同一偏好，进入正式对话时不得回到默认值。
8. `@` 弹层打开时，输入框 Tab 必须进入当前 Pane 的联网分段控件；控件内 Escape 和首段 Shift+Tab 必须关闭弹层并把焦点归还同一输入框。多 Pane 不得使用全局选择器定位设置控件。
9. Composer 浮层必须根据锚点上下空间自动翻转，并在视口四周保留至少 8px 边距；可用高度不足时缩短自身并让内容区滚动，不得以固定最小高度把弹层顶出窗口。

### 12.17 DSH ordered assistant turn 与实时流式规则（2026-08-16 用户确认）

本节是当前权威规则；涉及执行过程 Renderer、工具分组、reasoning 可见性、消息持久化和字符预算时，覆盖 §12.8、§12.9、§12.14、§12.16 中与本节冲突的旧描述。

1. Native、Claude Code、Codex 三种内核统一投影为一个按真实发生顺序排列的 assistant ordered timeline。每个 Run 在产品表面与新持久化数据中只对应一个 assistant turn，不按 Provider 轮次或工具轮次拆成多条助手消息。
2. timeline segment 类型为 `thinking`、带明确 `commentary | final_answer` phase 的 Markdown `text`、`tool` 和 `status`。除 `final_answer` 外，thinking、commentary、工具、重试、连接和终止统一收纳在一个“执行过程”外层折叠面板中，并在面板内按 segment sequence 保持真实顺序；最终回答独立位于面板之后；本轮「已更改文件」紧跟最终回答正下方，不进入执行过程面板。变更列表默认最多展示 4 条，其余通过底部「还有 N 个文件」下拉展开，展开时使用高度过渡。
3. 只有内核提供真实 reasoning/thinking 数据时才显示 Think。Think 默认是一行摘要，完成态取首个非空行，流式态取最新非空行；点击后在“执行过程”面板内原地展开完整 Markdown 内容，再次点击原地折叠，不创建第二层过程面板。用户可在执行过程标题旁或设置「显示思考过程」关闭 Think 行；关闭后时间线不再渲染思考摘要，工具段摘要与说明/状态行仍保留。底部活动条仍读取被隐藏的 Think，显示其最新一行，不得退回空泛的「思考中」或「等待模型响应」。
4. 每个工具调用独占一行。禁止 `调用了 N 个工具`、`×2` 或同名聚合；两次同名工具调用必须保留两条独立、稳定的行。被思考、说明或状态隔开的连续工具段可以收成该段自己的动作摘要（见 §12.36），展开后仍回到真实时间位置并逐行独立披露。
5. 工具主行显示用户可读的友好名称、关键参数摘要和 `running | completed | failed` 状态。工具结果通过 `toolCallId` 更新原行，不追加重复完成行；展开详情显示原始工具名、完整参数、输出、耗时和错误。
6. retry、model switch、connection、compaction 等运行状态各自占一行，并处于其真实时间位置。模型切换行必须带失败原因（例如「网关 502」），不得只写模型名。本地网关/传输故障先重试当前模型，不得立刻换成同一供应商的另一个模型。状态不得覆盖相邻 Think、说明、工具或最终回答，也不得伪装成模型 commentary。
7. commentary 与 final answer 都使用 Markdown 渲染，并由 phase 明确区分。最终回答不是“最后一个 text 猜测值”，而是 timeline 中 `phase: final_answer` 的文本；一个 assistant turn 的 footer 只在整个 turn 末尾出现一次。
8. 助手执行与回答区域不显示 Agent、模型或默认机器人头像；Composer、任务头和资源库仍可显示身份头像。Run 需要说明责任主体时允许使用紧凑身份文字，但不得恢复消息左侧头像列。
9. 新 Run 终态只持久化一个稳定消息 `asst-${runId}`。metadata commentary block 保存完整有界 timeline，兼容 blocks 只服务旧消费者和 Provider 上下文重建；Desktop 优先读取 timeline 并禁止重复渲染兼容 blocks。
10. 旧历史消息、旧 checkpoint 或缺少 timeline 的数据继续走 legacy fallback，不在读取时强制迁移。reasoning-only legacy 孤立消息继续隐藏；新 timeline 中只有 thinking 的合法 assistant turn 可显示。
11. transient frame 与 snapshot 可携带当前完整 timeline。所有已经到达的连续 text/thinking chunk 在下一次 `requestAnimationFrame` 合并为一次累计状态发布；不按模型名配置固定字速，不按 chunk 大小重新切片，也不保留客户端字符 replay 队列。
12. process、tool、terminal 与 reset 属于即时边界。边界到达时取消尚未执行的 RAF，把其前全部已到达文本连同边界按顺序立即收口；terminal 后不得留下待显示字符。
13. 流式 Markdown 使用 append-only 增量解析器：只保留最后两个顶层 Markdown block 为不稳定尾部，之前 block 按源码 offset 使用稳定 key 冻结，后续帧不得重新解析或重渲染冻结块。
14. 流式阶段延迟 syntax highlight、Mermaid 和 HTML embed 等富渲染；终态只执行一次完整 Markdown 解析与富渲染。该切换不得改变正文、链接、代码或表格内容。
15. 对话贴底使用稳定 flow-tip signature 处理消息边界，并由 `ResizeObserver` 跟随 Markdown、过程和图片的真实高度变化。禁止把完整 `messages` 数组作为每个流式帧的强制布局读写触发器；用户主动上滚后继续停止跟随。
16. Think、commentary、工具与状态行不显示 Markdown 输入光标，运行状态分别由 Think/tool spinner 表达；整个 assistant turn 最多只在最终回答末尾显示一个流式光标。
17. 所有行、展开详情、Markdown、状态与 footer 使用现有主题 token，在浅色和深色主题下保持可读；running 原位转 completed/failed 时不得重挂载整条消息或丢失用户的 Think/工具展开选择。
18. 对没有原生 phase metadata 的 Provider，Runtime 在 tool/terminal 边界前不能确定当前 text 是 commentary 还是 final answer。Renderer 必须把尚未被 timeline 分类的 `draft.text` 后缀作为过程车道里的流式 commentary 显示在当前顺序位置，不得进入最终回答气泡；边界分类后该后缀无损迁入对应 timeline segment。禁止把已到达文本藏到工具或终态边界再整段弹出。
19. “执行过程”面板在 Run 执行且最终回答尚未开始时自动展开；最终回答开始或 Run 进入终态时自动折叠。用户手动展开/折叠后，本 Run 内自动规则不再覆盖该选择；切换到新 Run 时清除手动覆盖并重新应用阶段默认值。历史完成消息默认折叠。
20. Provider 即使把工具前的短正文标为 `final_answer`，后续工具边界仍具有更高语义优先级：该工具之前的所有 text 必须归一化为 commentary，并按原 sequence 显示在“执行过程”面板内；只有最后一个工具之后的 final text 位于面板外。读取既有 timeline 时应用同一非破坏性归一化规则。
21. “执行过程”标题行同时显示当前活动摘要、过程项数和本 Run 总耗时，格式为“执行过程 · {当前活动} · N 项 · X秒/分/小时”。总耗时运行中依据 `startedAt` 每秒更新；终态优先使用 `RunProcessView.startedAt → completedAt`，Run process 尚未取回时从持久 timeline 的首尾时间推导，最后才使用 `durationMs`，折叠与展开状态下都保持可见。当前活动摘要与停滞分级见 §12.22。
22. 执行过程不提供“全部展开 / 全部收起”等批量披露控件；Think 与每个工具行只通过自身 Chevron 独立展开，用户的逐行阅读选择不得被全局操作覆盖。连续工具段的动作摘要只收纳该段工具行，不得同时展开或收起 Think 正文。
23. 步骤列表和命令结果按 NewMax 一次展示：进入执行过程后自动拼齐全部步骤和时间线分页，不显示「下一页步骤 / 继续加载」。展开工具后自动读取并拼接完整输出，不显示「读取完整内容 / 上一段 / 下一段」。超长输出仅做 NewMax 同款本地截断提示（4 万字符或 200 行），复制仍取已拼齐的全文。执行逻辑、步骤顺序和结果原文不得改写。聊天里的单轮文件卡与助手正文的按需原文读取保持原状。
24. 工作区「对话文件」、独立审阅窗口按 NewMax 一次列出全部变动，不显示「下一页文件 / 文件 1–N」。空态文案为「当前对话暂无文件变动」。聊天单轮「审阅文件」仍是本轮范围，面板「审阅会话文件」仍是整段会话范围。新建文档立即写入空的 `notes/未命名文档.md`（重名则递增），打开后默认富文本编辑，保存控件为「保存 / 保存中 / 已保存」，可选自动保存；不把未落盘正文标成「草稿」。不引入 TipTap/Monaco。

### 12.18 plan/exec 规划与执行规则（2026-08-16 用户确认）

规划与执行双模型把「先规划、审阅批准、再执行」拆成两段，各用独立模型（可配置思考强度）。设置位于「设置 → 模型 → 规划 & 执行模型」（app-setting `plan-act`：`enabled / planModelId / actModelId / planReasoningEffort / actReasoningEffort`）。

1. **触发**：裸 `/plan` 只打开或关闭本地模式预览，不创建消息、Run 或持久模式；发送 `/plan <需求>` 时先把 Conversation 持久化为 plan，再发送去掉命令前缀的需求。已经处于持久 plan 模式时，普通需求继续产生规划 Run。规划轮只读调研（写工具被拦截），内核通过 canonical plan item 或 `plan_submit` 提交正式方案并出现 draft 摘要卡。规划轮模型 = `planModelId`（配置时强制，覆盖手动模型选择）；提交与完成门禁以 §12.33 为准。
2. **模型路由（runtime 强制，单一事实源）**：`prepareRunBinding` 在 run 创建前按轮次路由——规划轮（对话 `interactionMode === 'plan'`）→ `planModelId`；**执行已批准方案的轮次（`appendMessage` 携带 `planExecuting` 标志，仅本轮）→ `actModelId`**；普通 execute 模式消息**不路由**，手动模型选择与 Agent 默认照常生效。对应角色的 `*ReasoningEffort` 随模型一并强制。未启用或对应角色未配置模型时走既有解析链。`ModelResolutionSource` 记录来源 `planAct`。执行模型只在批准方案后那一轮生效，避免普通聊天轮次被工作流模型覆盖。
3. **方案表面（NewMax 紧凑审批）**：draft 在 Composer 上方的 peek 表面显示标题、目标与步骤摘要，提供「批准并执行 / 要求修改 / 取消」。生产入口不挂载全字段就地编辑器，不把方案卡放回消息流。
4. **修改与版本**：「要求修改」切回 plan 模式，用户在 Composer 补充修改要求；模型下一次正式提交向同一 Plan 追加新 revision。`conversation.plan.revise` 继续作为存储/协议兼容能力，不对外声称当前生产表面可直接编辑。
5. **批准并执行**：`conversation.plan.approve` → 对话切到 execute 模式 → 发送执行指令（计划全文 JSON 内联，`buildPlanExecutionInstruction`）→ 执行轮由 `actModelId` 驱动；方案卡随后收起。执行轮展示与普通轮完全一致（§12.17 平铺规则）。
6. **版本历史**：Runtime 持久化保留全部 revision 供审计与兼容 API 读取；NewMax 紧凑审批表面只展示最新 draft，不渲染未挂载的版本 chip 或历史编辑入口。
7. **取消计划**：「取消」调用 `conversation.plan.cancel` 使计划进入 cancelled 并以 peek 退场；「要求修改」的交互以规则 4 为准。
8. **生效模型提示**：Plan Banner 显示“规划模式 · 只读”、当前生效的规划模型、执行模型和设置入口；plan-act 未启用或对应模型未配置时回退显示 Composer 当前模型。执行方案轮由批准动作触发，普通 execute 模式不显示 Plan Banner。界面不得展示当前实现并未提供的“忽略了所选模型”附注。
9. **与任务清单的关系**：方案卡是批准前的人类审批计划，持久化且带版本；右上角 Progress 是模型在当前 Run 内维护的任务进度。两者可以先后出现但语义与事件来源必须分离，任务清单不得生成或替代正式方案卡；展示位置与生命周期以 §12.24、§12.27 和 §12.33 为准。

> §12.19 曾替换本节的审批与任务清单形态；当前任务清单展示以 §12.24、§12.27 为准，正式方案提交、审批与 Composer 位置以 §12.33 为准。

### 12.20 定时任务与随机任务（2026-08-16 用户确认）

定时任务 = 绑定执行者（智能体 / 直接模型）的专属会话 + 触发规则 + 触发时注入的指令。规则四种：`at`（单次）/ `every`（固定间隔，≥5 分钟）/ `random`（每日窗口随机 N 次）/ `cron`（croner 表达式，任务时区）。

1. **任务模型**：`ScheduledTask { name, instruction, target: {kind:'agent'|'model', ref}, rule, timeZone, enabled, nextRunAt, lastRunAt, lastResult, conversationId }`。执行者二选一：智能体（会话 track='agent'，人设/模型/技能全套生效）或直接模型（track='model'）；会话标题「任务 · {名}」，会话列表带「任务」徽标，可正常进入聊天与手动接管。
2. **调度引擎（runtime）**：30s 心跳（单飞防重入）扫描 `next_run_at <= now` 的启用任务；`nextRunAt` 持久化（任务表列），重启恢复天然成立。触发 = 惰性创建任务会话（inbox 派生）→ 注入用户消息「【定时任务 · {名}】{指令}」→ 走普通 run 路径（`prepareRunBinding` + `executeKernelRun`，仿 goal 轮次，不经 socket）。触发前先落库（nextRunAt/lastRunAt/lastResult），崩溃最多重复一次触发。
3. **规则推算**（`task-scheduler.ts` 纯函数）：`at` 触发后无下次；`every` = 触发时刻 + 间隔；`cron` = croner 下一次（任务时区）；`random` = **确定性日计划**——seed(任务 id + 日期) 生成当日 min..max 个窗口内随机时刻（等分随机，重启重算一致），取 lastRunAt 之后第一个，当日耗尽则取明日计划首个。
4. **并发与错峰**：全局任务并发上限默认 2（app-setting `task-scheduler.maxConcurrent`，1-5 可调）；达到上限的到期任务跳过并记 `skipped（并发上限）`。同一 tick 多任务按任务 id 排序逐个触发、间隔 2-5s（随机任务天然错峰）。浏览器自动化为共享单实例，靠上限 + 错峰缓解冲突；MCP 连接器与文件写冲突同理靠上限缓解（文档提示自动化任务建议错开时段）。
5. **错过执行**：恢复后 tick 发现 `nextRunAt` 已过期 → 补跑一次（先落库再触发）；不设顺延（at 任务触发后完成）。
6. **会话忙**：任务会话有 in-flight run 时跳过本次并记 `skipped（会话忙）`。
7. **命令与事件**：`scheduledTask.create/list/update/delete/trigger`；事件 `scheduledTask.updated / fired / skipped`（桌面端据此刷新）。
8. **模型工具 task_schedule**（平台工具，全内核）：action `create | list | cancel`；create/cancel 在 ask-mode 下走工具审批（复用审批卡），list 免审批；规划模式目录不注入（`PLANNING_MODE_DENIED_TOOLS`）。
9. **UI（侧栏「定时任务」stage）**：任务卡片列表（名称、执行者、规则摘要、下次触发本地时间、最近结果 ✓/⏭/✗、启停开关、操作：立即触发/编辑/删除/打开任务会话）；新建/编辑对话框——名称、指令、执行者两组下拉（智能体库带人设摘要 / 模型目录带供应商）、规则四 tab（单次 datetime-local / 周期分钟数 / 随机窗口+次数 / cron 表达式）、时区下拉（UTC/常见 IANA）、必填与合法性校验（单次须晚于当前、周期 ≥5、随机 min≥1 且 max≥min、窗口 HH:mm）。
10. **与 goal 模式区分**：goal = 一个目标的持续自动推进（评估器判完成）；定时任务 = 到点干一件事（独立规则）。任务触发的 run 是普通 run，互不干扰。

### 12.21 目标模式增强与本地 Skill 发现（2026-08-16 用户确认）

**目标模式**（在既有 goal.set/get/clear + 评估器自动续轮基础上增强，对齐 DSH）：

1. **状态机**：`active ⇄ paused`（暂停/恢复）、`active → blocked`（模型报受阻或轮次耗尽，可 resume）、`active → achieved`（评估器 met 或模型 complete）、`cleared`。持久化扩展 `GoalStatus`：`maxGoalRounds`、`roundsStarted`、`pausedAt`、`blockedAt`、`blockedReason`。
2. **轮次上限**：`goal.set` 可带 `maxGoalRounds`（默认 5）；`roundsStarted` 达上限且评估未 met → 自动 `blocked（已达轮次上限）`，停止续轮（防无限烧 token）。
3. **结构化轮次提示**：自动轮注入 `<goal_round>` 块（Objective / Round N/max + 继续指示 + 完成前取证并 complete / 受阻才 block）。
4. **模型工具 goal_manage**（平台工具全内核）：`complete`（自证完成）/ `block`（受阻说明停下）/ `progress`（进度记录）；仅该对话有 active goal 时才进入工具目录。任务清单不是 Goal 模式，必须走 `update_task_plan` / TaskCreate，并显示在 Composer 任务清单，而不是 Goal 状态卡。complete 直接标记 achieved。
5. **命令**：`goal.pause` / `goal.resume`（恢复即续轮）；事件随 goal 状态变化。
6. **目标状态投影**：状态徽标、objective、轮次进度、暂停/恢复、编辑、清除、最近评估与受阻原因继续使用 Runtime 的 `GoalStatus` 作为唯一事实源；原 GoalCapsule 展示入口已由 §12.24 的 ZCode 浮动状态卡取代。
7. **聊天可见性**：设置目标后的第一轮必须把原始目标文字作为普通用户消息持久化到聊天；自动续轮使用“继续目标（第 N/M 轮）：目标”作为用户可见文字。`<goal_round>` 控制提示只进入模型上下文，不得作为用户气泡暴露。
8. **轮次路由**：`goal.set` 冻结当前 Composer 的模型、内核、思考强度与联网状态，所有自动轮复用该路由；恢复暂停或受阻目标时用当前 Composer 路由覆盖旧绑定，避免回退到会话创建时的模型。状态卡轮次必须显示“第 N/M 轮”，不使用缺少语义的裸比例。

**本地 Skill 发现与导入**（对齐 NewMax 目录库）：

7. **来源顺序**：当前/其他已绑定工作区的 `<workspace>/.claude/skills` → Claude 设置中明确启用且存在本地缓存的插件 `<home>/.claude/plugins/cache/<marketplace>/<plugin>/<version>/skills` → SYNC-THINK 全局库 `<home>/.sync-think/skills` → 用户级 `<home>/.claude/skills`。插件 ID 使用 `plugin@marketplace`，用户、项目和本地设置按作用域合并，后者的显式 `false` 可覆盖前者的 `true`。每个直接或嵌套 Skill 以包含 `SKILL.md` 的目录为单位识别，忽略 `_disabled`、node_modules、`.git`、dist 等；junction/重叠来源按真实文件路径去重。
8. **自动登记与 watch**：runtime 启动和 `skill.local.scan` 时把有效本地 Skill 登记为不可变 SkillVersion；工作区来源以及项目/本地作用域启用的插件来源同步建立对应工作区激活关系。相同名称但内容发生变化时创建新版本；同一真实目录被多个工作区引用时合并来源并保留全部工作区 ID。所有存在的来源目录使用 recursive watch（debounce 300ms），UI 30s 重扫兜底并刷新“我的 Skill”。
9. **命令**：`skill.local.inspect {path}` 检查文件夹、`SKILL.md` 或 ZIP 并返回一个或多个 Skill 元数据；`skill.local.scan` 返回候选、来源、已导入与 watch 状态；`skill.local.import {path, scope, overwrite?}` 安装到全局库或目标工作区。导入弹窗的名称、描述和图标属于独立显示元数据，不改写原始 `SKILL.md`。
10. **完整目录安装**：导入必须复制 Skill 根目录的全部内容，保留 `scripts/`、`assets/`、`references/` 与模板文件，不能只把 `SKILL.md` 文本写入数据库。根级 `SKILL.md` 的 ZIP 使用 ZIP 文件名作为安装目录；只有一个顶层包装目录时使用该目录名；`skills/<name>/SKILL.md` 包按 `<name>` 分别安装。多 Skill 包逐目录安装；同一请求可选择全局和多个工作区，Renderer 按目标位置逐项调用并汇总结果。同名目录先返回冲突清单，用户确认后对全部已选位置以 overwrite 重试；部分失败时保留弹窗和输入。安装成功后登记 SkillVersion，工作区安装立即激活，并刷新“我的 Skill”。

### 12.22 执行活动可见性与停滞分级（2026-08-17 用户确认）

本节补充 §12.17 规则 21：面板折叠后必须仍能回答「现在在做什么」和「这是卡住了还是还在跑」。

1. **活动摘要**：由有序过程项派生（`process-activity.ts`，纯函数），优先级为 运行中的工具（`{友好名} {关键参数}`，摘要截至 40 字）→ 最新 Think 行 → 正在回复 → 最新运行状态行 → 最近 Think 行（等待下一步时）→ 兜底“等待模型响应”。Think 开关只隐藏时间线行，不撤下活动条里的思考原文。运行中的工具优先级最高，即使其后已有说明文字到达——工具执行期间“在做什么”的答案仍是那个工具。Run 进入终态后摘要消失，只留“执行过程 N 项 · 总耗时”。
2. **活着的证据**：摘要文字使用 gradient sweep（`background-clip: text` 扫光）表示进程存活——静态文字无法区分渲染卡死与正常等待。必须提供 `prefers-reduced-motion: reduce` 降级（去掉扫光，保留纯色可读文字）。
3. **运行中耗时**：running 工具行主行显示自增耗时；终态耗时回到展开详情内，主行不再显示。所有计时共用面板层唯一的秒级时钟，禁止每行各自 `setInterval`——否则违反 §12.17 规则 17（running→completed 原位翻转不得重挂载）。
4. **停滞分级**：以“最后一次可见进展”为基准，措辞保持中性（长 build/test 跑几分钟是正常的，不得称为“卡住”）。有工具在跑时宽容（>120s 提示、>300s 标记“长时间无输出”）；无工具在跑却无输出才严格（>15s 提示、>60s 标记），后者才是真正可疑的情况。
5. **工具实时输出（`tool_progress`）**：running 工具行下方显示最新一行输出。该帧为**纯广播瞬态**——不写事件流、不进 `transientReplay`（256 帧预算不得被长命令冲爆）、不进 snapshot；重连客户端靠 `startedAt` 计时并等下一帧。它是**注解而非边界**，不得取消 §12.17 规则 12 的 RAF 文本合批。
6. **覆盖范围**：`tool_progress` 仅 native 内核可得（工具在 Runtime 进程内执行）。claude-code / codex 的工具在其子进程内部执行，中间输出不经过 Runtime，只能降级为规则 3 的自增耗时。
7. **状态标记**：工具状态只用图标表达——running 转圈 / 完成 ✓ / 失败 ✗（成对的勾与叉），不再渲染“运行中 / 完成 / 失败”文字；文案移入 `title` 与 `aria-label`，保留悬停提示与读屏可读性。

### 12.26 执行 Loading State、Streaming Text 来源与文件树（2026-08-28 用户确认）

本节覆盖 §12.23 规则 1 中“折叠标题显示当前活动”的旧位置约定；活动派生、停滞阈值和唯一秒级时钟继续沿用 §12.22。

4. **流式来源链接**：回答中的 `http/https` Markdown 链接渲染为紧凑来源 chip，显示对应连接器图标与原链接文字；YouTube、Reddit、LinkedIn、Instagram、TikTok、X、知乎、哔哩哔哩、微博、小红书、抖音、快手等复用本地连接器资产，未识别域名使用 Globe。流式阶段只渲染已经形成的完整 Markdown link，不猜测未闭合 URL。

9. **唯一等待标记**：底部活动行的 `3 × 3` 像素格是执行中的唯一等待动画；已有活动行时，消息气泡不得再追加第二组三圆点 TypingDots。

16. **站点图标**：连接器目录已知域名继续复用本地连接器资产；产品参考站点等已确认域名可登记独立本地图标，例如 `beautifului.dev` 使用官网 PNG。应用不为来源图标放宽 CSP，也不在渲染时向任意站点请求 favicon；未登记域名继续使用 Globe。
17. **活动高亮可见性**：底部活动文案继续使用常驻可读底色文字与独立伪元素扫光层，避免图片背景把 `background-clip: text` 冲掉。扫光本身对齐 Beautiful UI Loading State：`90deg`、次要色→主文字色→次要色、`1.4s`、`200%` 画布、`150% → -50%`。审批等待不加扫光。running Think/工具行的扫带中心对比度高于两侧，但不得掩盖文字、状态或点击区域。

### 12.27 目标状态、任务清单触发与滑动 Tabs（2026-08-28 用户确认，2026-08-31 更新）

5. **轮次语义**：状态卡“第 N/M 轮”表示已启动并完成的 Goal 工作轮数 / 自动轮上限，不表示任务清单完成数。任务完成数由 Progress 独立展示。
6. **续轮内容**：自动续轮的用户可见消息包含“继续目标（第 N/M 轮）”与 Runtime 的 `lastReason`；内部提示只继续未覆盖工作并核对新增证据，不重复已完成内容。状态标记只控制循环，不作为用户可见结论。
7. **清单触发**：多步骤任务只有在模型真实调用 `update_task_plan`、`TaskCreate / TaskUpdate / TaskList` 或 Codex 发出 `turn/plan/updated` 后才显示任务清单。普通自然语言中的“我会分三步”不反推清单；单步骤任务也不强制出现。
8. **清单生命周期**：首次收到当前 run 的有效计划时，右上状态卡自动显示任务清单；即使计划快照与 run 终态在同一批次到达，也必须展开一次。run 完成后保留最终清单，直到当前对话的下一次 `run.started` 清空；其他 thread/task 的运行事件不得影响本清单。计划参数同时兼容顶层 `arguments / args` 与 Codex 的 `toolCall.argumentsJson / arguments / args`。
9. **测量式 Tabs**：标准互斥 Tabs 使用共享滑动底板，按活动 tab 的真实 `offsetLeft / offsetWidth` 设置位置和宽度。时序使用 `--motion-tabs-duration: 250ms` 与 `--motion-tabs-ease: cubic-bezier(0.22, 1, 0.36, 1)`；文字颜色与底板同步过渡。
10. **初始化与适用边界**：首次绘制和 window resize 时暂停 transition、强制布局后恢复，避免首屏飞入或窗口缩放拖影；tab 选中状态变化、文字权重变化或组件重渲染不得触发无动画吸附，也不得用元素 `ResizeObserver` 覆盖正在进行的位移动画。`prefers-reduced-motion` 下无过渡。设置分类、模式切换、模型类型、能力中心、智能体详情与文件视图适用；可拖拽、可关闭、可重排的会话/文档 tabs 保留独立交互。
11. **计划事件关联**：`tool.requested` 可携带工具名与参数，后续 `tool.completed` 可能只携带同一 `toolCallId` 和结果。Runtime 与 Desktop 必须用调用 ID 继承原工具名，以完成结果覆盖请求态清单；计划事件不得退化成普通 `Tool` 行进入执行时间线。

11. **共享菜单与空态动作**：加号图标随菜单开合旋转；Slash、MCP、加号与对象选择 Popover 使用 `150ms` 时序。菜单与 Composer 等宽、间距 `8px`、最大高度 `420px`，支持上下方向键、Enter、Tab 和 Escape。输入 `@` 与点击加号打开同一动作表：附件、Plan、Goal、会议纪要、联网设置、权限模式与工作区文件搜索。继续输入则按 `@` 后的文本过滤工作区文件；选中项会吃掉 `@` 查询片段。空态工具栏直接提供模型 / Agent / Team 对象选择器，右侧保持单一稳定动作槽：草稿为空时显示语音，存在可发送内容时原位切换为发送。
12. **审批层级**：正式方案审批和工具审批只挂在会话态 Composer 上方，以稳定 peek 动效进入，不作为消息流中的普通聊天内容。审批权限选项只展示协议已真实支持的范围；会话级允许由 Runtime 按 Conversation 保存，应用级永久允许必须同时具备持久化、设置页查看和逐项撤销合同，不能只增加按钮文案。
13. **键盘与响应式**：Slash、MCP、加号和文件菜单都必须保持单一活动索引，方向键移动时确保活动项完整可见，Enter 执行，Escape 关闭并归还输入焦点。窄 Pane 可隐藏次要文字但不得隐藏退出 Plan、Goal 控制、发送或权限状态；任何菜单、Banner、审批表面和文本均不得覆盖相邻内容。
14. **自然语言模式建议**：普通文本按 NewMax 原始 Plan/Goal 关键词规则检测最先出现的意图；建议条位于 Composer 上方，包含模式图标、创建文案、`Shift + Tab` 键帽、接受和关闭。接受时仅添加模式前缀并保留正文，关闭只抑制当前文本版本；进入任一模式、打开菜单或 Composer 禁用时不显示。
15. **Goal 状态协议**：每轮继续使用当前 Composer 工作模型；Runtime 通过模型结果中的 `GOAL_STATUS: complete|continue|blocked` 更新真实 Goal 状态并决定续跑，不再暴露或强制依赖独立 evaluator model。无状态结果只能继续到既有轮次/Token/停止条件门禁，不得由 Renderer 假设完成。模型设置不再展示或保存独立 evaluator，目标状态面板也不显示 evaluator 是否配置；遗留 `evaluatorConfigured` 只保留协议兼容，不参与 Renderer 呈现或 Goal 可用性判断。
16. **审批范围与撤销**：工具审批横条按 NewMax 顺序显示“批准 / 本会话允许 / 拒绝”；本会话允许由 Runtime 记住当前 Conversation 的同名工具。仅当 Computer Use 工具参数含合法 Windows `app_id` 或 macOS bundle id 时，中间动作显示“始终允许此应用”，并把规范化应用标识持久化；Renderer 不自行缓存或伪造授权。设置页列出这些已授权应用并支持按规范化标识逐项撤销，撤销后该应用下一次调用重新进入审批。`human-only` 工具始终只显示单次“批准 / 拒绝”，每次请求都重新等待真人决定；“本会话允许”和“始终允许此应用”均不得出现，Runtime 对伪造或旧客户端提交的这两类决定也必须拒绝。
17. **最终接线**：`NewMaxComposerFrame` 是空态和会话态唯一的输入区宿主，`ComposerEditor` 是两处唯一的文本编辑器；两处必须接入同一套 Plan/Goal 激活态胶囊和自然语言模式建议。正式方案与工具审批依赖已存在的 Conversation/thread，只挂载在会话态 Composer 上方的共享 peek 叠层。旧输入框分支、消息流审批卡或独立空态 Composer 不得作为回退路径继续存在。
18. **CodeMirror 编辑器边界**：`ComposerEditor` 使用 CodeMirror 6 的 `@codemirror/state`、`@codemirror/view` 与 `@codemirror/commands`，每次挂载只创建一个稳定 `EditorView`；启用行折行、历史/默认键盘映射、IME 安全的 Enter 提交、焦点/选区桥接和原子 Skill/附件/粘贴引用 token。隐藏的兼容性 `<textarea>` 只服务既有调用方和测试，不参与布局或作为第二编辑器；工作区文件编辑仍遵循规则 7。

### 12.34 AI 设计稿预览与保存合同（2026-09-01 用户确认）

1. **唯一识别格式**：用户明确要求创建 UI mockup、视觉设计、原型或设计稿时，模型输出唯一的 `design-html` fenced block，内容为完整、自包含 HTML 文档；CSS/JavaScript 可内联，页面必须有可见内容和可访问交互。普通 HTML 示例继续使用 `html` fence。
2. **预览与校验**：Renderer 只把通过标签结构、可视元素、嵌套标记和 1 MiB UTF-8 上限校验的 `design-html` 当作设计稿；流式阶段先按代码块展示，完成后才挂载预览。新版本校验失败时保留上一版，不把错误内容写盘。
3. **事实边界**：设计稿预览、在系统浏览器打开和保存到项目是三个独立状态。模型只有在真实 `browser_open` 或项目相对路径 `write_file` 返回成功后，才可声称对应动作完成；不能从 fence、自然语言或静态路径推断已打开/已保存。
4. **操作入口**：设计稿卡提供预览/源码切换、复制、刷新、浏览器打开、下载和保存到项目；保存使用项目相对 `designs/<slug>.html` 路径并保留并发修改检测。设计稿创建入口通过真实对话和既有工具合同执行，不在 Renderer 静态伪造工具结果。

### 12.35 NewMax 浏览器与双设计稿工作区（2026-09-02 已实现，待最终实窗门禁）

### 12.36 执行过程 Think 开关与动作摘要（2026-09-05 用户确认）

1. **Think 可见性**：执行过程标题行右侧提供独立 `显示 Think` 开关，不得放进「执行过程」折叠按钮内部，避免点开关同时折叠面板。关闭后该轮时间线不再渲染 Think 行；偏好写入 `showThinking`（默认开），设置 → Agent → 显示 中的「显示思考过程」与标题开关同步。
2. **就地段折叠**：执行过程不把整轮工具收成一条总摘要。思考、说明、状态仍按真实时间位置留在正文里；只有被这些节点隔开的连续工具段（至少 2 条）各自收成一条中文动作摘要，例如「探索了 3 个文件，运行了 7 个命令」。零次类别省略。探索/编辑按路径去重，搜索和命令按调用次数。点击某段摘要只展开这一段的独立工具行，禁止 `×N` 聚合。单独一条工具不折叠。
3. **披露默认**：某一段含 running 工具时保持展开。该段全部完成（成功或失败）后自动收起，不再因为失败、仍在等待最终回答或后面还没出现下一段正文而保持展开。测试 `defaultOpen` 时保持展开。与外层「执行过程」折叠无关。
4. **空态**：若本轮只剩被隐藏的 Think，标题行和开关仍保留，用户能重新打开 Think。底部活动条继续显示最新 Think 行。
5. **对话浏览器工具**：当前对话里的 `browser_open` / `browser.command_requested` 打开或聚焦右侧工作台浏览器标签，不把主区域对话挤走。同一轮里多条成功的 `browser_open` 都要处理：同一 URL 只聚焦已有工作台页，不同 URL 各开一页，不得只留下最后一条，也不得改写已打开的其他网站。打开网站默认只出现浏览器标签，不自动停靠「工作区文件」。用户从主窗格加号手动打开的浏览器仍可落在 Pane 内。

### 12.37 beUI 内容展示适配（2026-09-05 用户确认）

1. **范围与真源**：适配 Code Block、Tool Result、File Diff 的信息层级，使用现有 React、highlight.js 和主题 token；不引入第二套执行状态、AI SDK 或高亮引擎。Claude Code / Codex 原生事件、持久化和任务清单链路不变。工作区文件夹标签的切换/排序动画见 §12.38。
2. **代码块**：普通代码采用紧凑文件/语言栏、生成状态、行号、高亮和复制反馈；有真实路径时才显示文件名。长代码保留展开收起，代码区独立滚动。用户上滚或使用 Home/PageUp 后暂停跟随，回到底部或点击「回到末尾」才恢复；流式 token 更新复用代码 DOM。Markdown 中 Mermaid、HTML、设计稿、Excalidraw 等专用内容的原有分流保持不变。
3. **性能与复制**：高亮复用现有语言注册，使用组件级 memo 和 deferred 更新，不缓存每个历史流式版本；大于 100,000 字符时退回纯文本高亮。代码块最多预览 2,000 行并明确提示，复制仍取完整源文，不混入行号或状态文字；复制失败显示真实反馈。跨行高亮 span 在每行闭合并重开，避免多行注释染色丢失。
4. **工具结果**：保留工具摘要、资源跳转、耗时和 Think 时间线；参数/结构化 JSON 保留字段视图与原文复制，普通输出使用有行号的代码面板。展开工具后直接显示已拼齐的完整输出，不要求用户再点「读取完整内容」或翻段。存在实时结果时默认展开；完成后无论成功或失败都自动收起，与 §12.36 一致。用户手动展开后仍可查看失败详情和复制错误。明确的外层 defaultOpen 优先。不添加未接通的重试入口，也不让代码块的完成标志冒充工具成功。
5. **文件差异**：继续使用真实新旧快照和现有 LCS 行级 diff，文件卡路径、打开/审阅入口和增删统计保留。差异区显示独立的新旧行号、增删底色、源码高亮、换行选项和修改后内容复制。缺快照、截断快照或超出 400 行差异计算边界时明确降级，不展示伪完整 diff；空文件不生成虚构的删除空行。文件差异分页与「本行已缩略 · 读取完整行内容」后的按需原文读取保持原状，不自动拼装全文。
6. **外观与可访问性**：三类表面沿用明暗/壁纸主题令牌和紧凑间距，窄聊天列在内部滚动而非撑宽列；复制、展开、回到末尾具备明确标签和键盘焦点，reduced-motion 关闭新增旋转动画。

### 12.38 工作区文件夹标签 Morphing（2026-09-06 用户确认）
