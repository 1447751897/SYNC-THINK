## 一、性能问题（按影响排序）

### P0-1 能力页每 30 秒强制磁盘重扫 + 4 个并发 IPC ✅ 已复核

`apps/desktop/src/renderer/shell/abilities/AbilityCenterPage.tsx:399-403`

```ts
useEffect(() => {
  void loadLocalSkills();
  const timer = window.setInterval(() => void loadLocalSkills(), 30_000);
  return () => window.clearInterval(timer);
}, [loadLocalSkills]);
```

`loadLocalSkills`（:387-397）做两件事：
1. `api.skillLocalScan({ refresh: true })` —— **强制重扫磁盘**
2. `await loadCatalog({ background: true })` —— 再并发 4 个 IPC（`listSkills(500)` / `listSkillMarket` / `listMcpServers(100)` / `listCapabilityGovernance`）

放大器：`KeepAliveLayer` 用 `hidden` 保活而非卸载（`KeepAliveLayer.tsx:11-17`），所以**切走页面后轮询永不停止**。

并行结论（另见 P0-2）：runtime 侧 `handleSkillLocalScan` 是**同步递归磁盘扫描**（`runtime.ts:13013`，depth≤4 / MAX_FILES=500，每个 SKILL.md `readFileSync`），在 socket 帧处理函数里同步执行 → 阻塞 runtime 事件循环，其他客户端 IPC 全部排队。📋

**影响**：打开一次「能力」页后，每 30 秒一次全量磁盘扫描 + 5 个请求，永久持续。
**修复方向**：轮询改为「页面可见时才跑」+ 有变更才 refresh（去掉无条件 `refresh: true`）+ 把 runtime 侧扫描移出同步路径。

### P0-3 「使用统计」每次进入都重新加载 ✅ 已复核

根因链（三条全部核实）：

1. `ModelSettings.tsx:5084-5086` —— `useEffect(() => { void load(); }, [load, reloadToken])`，**挂载即加载**，无模块级缓存
2. `KeepAliveLayer.tsx:11-13` —— `const visited = useRef(props.active)`，**实例销毁即丢失已访问状态**
3. `ShellApp.tsx:4149 / 5821` —— `SettingsModal` 用 `<Dialog.Root open={settingsOpen}>` + `<Dialog.Portal>`，**没有 `forceMount`** → 关闭设置即卸载整棵 `SettingsPage` → 所有 `KeepAliveLayer` 的 `visited` 重置

有力旁证 ✅：仓库里**已经有**现成的 TTL + in-flight 去重缓存 `provider-usage-summary.ts:109`（`usageCache` / `usageInflight`），但 `ModelSettings.tsx` 完全没 import 它（全仓仅 `ChatView.tsx:272` 引用该模块）。

**修复方向**：给设置弹窗 `Dialog.Portal` 加 `forceMount`（配合 `data-state` 控制显隐），或把 usage 数据提升到 shell 级 store 并复用现成缓存。

### P1-1 `refresh()` 全量重拉 + 全量序列化写盘，约 20 处调用 ✅ 已复核（调用点数量来自子代理 📋）

`ShellApp.tsx:1580-1680`：单次 `refresh()` 顺序发起 6 个 IPC（`listConversations({includeArchived:true})` **无分页/无 limit** + agents + teams + providers + workspaces + skills），随后 `writeShellBootSnapshot`（`JSON.stringify` 全量写 localStorage）+ `persistPaneLayouts`（3 次 localStorage 写）。全函数**无 try/catch、无 in-flight 去重**。

## 四、竞态与可复现缺陷

### B-1 `ActivityCenterPage` refresh 无 requestId 守卫 📋

`ActivityCenterPage.tsx:142`（refresh）+ `:218`（`if (fresh) void refresh()`）
挂载时 `void refresh()`（:180）与事件驱动 refresh 可并发，无防抖/无 generation 校验 → 慢的旧响应可能覆盖新结果，出现「筛选后列表与筛选条件不匹配」的陈旧数据。
对照：`AbilityCenterPage.tsx:348` 有 `loadRequestRef` 校验，是正确的做法。

### B-2 `AbilityCenterPage.loadLocalSkills` 错误静默吞掉 ✅ 已复核

`AbilityCenterPage.tsx:394-396` `catch { /* 扫描失败保持现状。*/ }` —— 扫描失败无任何提示，用户看到的是陈旧列表。

### B-3 `refresh()` 无错误处理 📋

`ShellApp.tsx:1580` 无 try/catch，任一 IPC 失败即 unhandled rejection 且界面停空。

### B-4 `project-git` 每 5s 派 7 个 git 子进程 📋（生产可达性待确认）

`main/project-git.ts:169` `getProjectGitInfo` 并发 spawn 7 个 git 子进程 + 对每个未跟踪文件 `readFileSync` 计数；`TaskStatusPanel.tsx:796` 以 5s 周期 + window focus 反复触发。
子代理结论：`TaskStatusPanel` 目前仅被 QA 入口（`Phase3VisualFixture.tsx:1354` → `qa-entry.tsx`）引用，**生产路径未接入** —— 一旦接入即为高频子进程风暴。
