# ADR 0003：用户拥有智能体定义，群聊组合小队工作链

- 状态：已接受
- 日期：2026-09-29
- 范围：Runtime、协作协议、存储、桌面智能体聊天

## 领域词汇

- **智能体定义**：持久化的名字、人设、模型、技能绑定；不是运行实例。
- **委派执行**：临时给已有且当前工作区可用的智能体分配任务，生成运行记录；不创建定义。
- **小队**：可复用的成员、内部负责人、串并行策略与依赖图。
- **群聊**：用户交互与外层调度容器，拥有一个明确的协调员，可同时包含普通智能体和完整小队。
- **小队参与者**：群聊的顶层成员（kind=team），保留加入时的 teamSnapshot；内部执行身份采用 team:<teamId>:agent:<agentId>，不与独立加入的同一智能体混淆。

## 决定一：定义管理不等于自动招募

用户明确要求创建/修改时，主回复轮才提供匹配的 create_agent/update_agent 和资源查询工具。宿主根据原始用户消息判定工具资格；计划模式、被委派运行、工作流 task/summary 和智能体发来的消息不获得管理资格。自然语言识别只是保守的工具资格门槛，最终变更还须逐次确认；没有识别到明确意图时，请用户明确提出创建/修改请求。

定义变更在 ask/workspace/full-access 下均要求 once 审批，不复用会话级授权。Native 和外部内核共享目录过滤与执行守卫。保存定义不启动运行、不加入小队；该管理轮次也不允许 agent_run/agent_delegate 或协作工作流工具继续派活。执行另起用户轮次。

已有智能体的普通调用与可配置并发委派保持分离。委派执行不隐式创建定义，被委派成员不再次扩大协作范围。技能、小队管理和归档沿用原有权限层级。

与 ADR 0001 的关系：用户主动提出的配置管理是宿主操作，不授予工作区文件写权限；协作界面提供持久审批卡。无人值守的任务轮没有此入口。

## 决定二：小队嵌套于群聊，继续复用现有调度器

群协调员调度顶层普通智能体/小队；小队保留内部负责人和工作链。宿主将小队节点展开为作用域化内部 DAG，加一个由内部负责人执行的验收交付节点。外层依赖指向交付节点；小队的根节点承接外层前置依赖。交付节点等待内部叶子节点，不占执行槽等待自己的子节点，避免并发槽/资源锁互相等待。

冻结 DAG 的派发/结果受每批最多 64 节点约束，不挤占智能体自动聊天的循环预算，避免多个小队的正常交付吃掉最终汇总额度；对等自动消息仍保留原跳数/数量上限。

内部结果路由给小队负责人；负责人验收结果回群协调员。任务仍使用 ADR 0002 的 document/file 合同，失败依赖不继续执行，旧 attempt 不冒充新交付。内部成员不重复显示为群顶层成员，任务详情仍可追溯身份。

新增成员/小队只参与后续工作流，不重写已派发 DAG。成员更新带 expectedTopologyRevision，冲突要求刷新。任务保存协调员、拓扑版本和小队作用域；执行中不移交协调权，先完成/停止原任务。移出成员须先处理其活动任务，移出小队级联停用内部成员；取消小队交付节点一并取消其内部前置节点。加入时固定小队定义，新定义通过退出后重新加入采用。

选用编译到已有调度节点而非另建 WorkflowInstance 引擎，以复用原有持久化、产物、重试、并发/资源锁机制。当前不做运行中自动重排；需要改计划时先停止旧轮，再派发新轮。

## 协议和兼容

- create 增加 teamIds；保留旧 teamId（直接与小队对话）语义，二者不混用。
- members 增加 addTeamIds 和 expectedTopologyRevision。
- member 增加 kind=team、teamParticipantId、teamSnapshot。
- task 保存 coordinatorMemberId、topologyRevision、teamParticipantId。
- 采用现有 JSON 快照存储，无新增数据库表。旧字段缺省可读；旧小队聊天继续沿用已有策略。
- 本次 executionVersion=3，扩展 ADR 0002 的 v2 引擎；新界面连接旧后台保留历史读取并提示重启，阻止旧后台静默忽略新增的成员/工作流字段。
- 新建普通群聊可显式选协调员；已有群聊从成员面板添加小队。群聊标题以 Conversation.title 为准，重命名同事务同步快照，启动修复历史投影。

## 展示与已读

空答案不绘制内容气泡，暂停/失败信息继续显示。模型或代理连接故障仍按真实错误展示，不用空白条掩盖。

已读由当前前台且有焦点、消息已加载、滚动到最新结果的视图确认，回传实际展示的 runId 集合，宿主 UI 只推进对应终止事件游标。历史聊天的未读继续保留并在历史菜单标注。沿用本机 localStorage 游标，不宣称具备跨设备已读同步。

## 验证

重点用例覆盖管理资格与执行拒绝、所有权限级别逐次审批、Native/外部目录一致、渲染后已读、标题事务和启动修复、小队命名空间与 DAG、冻结版本、新成员不改变当前轮、拓扑冲突、忙碌成员移出阻止、小队停止和分层结果路由。
