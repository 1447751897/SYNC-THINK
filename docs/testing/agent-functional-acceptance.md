# 智能体完整人工验收：群聊与自动协作

日期：2026-10-01。适用协作执行协议 v6。

## 本版交互

所有多人会话统一叫「群聊」。小队是可复用的成员组合，不是左侧的另一种会话。点击左上角「＋」或群聊栏「＋」，在新建对话中选择小队卡片，再创建群聊。左侧只列实际群聊和私聊。

默认模式为「聊天」：先沟通，当前用户明确说开始或确认执行方案后，协调员调用真实工作流。工作目标可以由协调员在开工时整理，也可以手动通过「设置工作目标（可选）」填写，不要求每次先填表。

「只讨论」刻意限制派工；「分配小工作」显式创建工作，成功发送一次后自动回到聊天。普通进度询问不应产生新的文档任务。

## 准备

- 使用专门的测试群，每次只写约300字，先跑通流程再写长篇。
- 检查成员使用的真实模型可用；真实调用会消耗供应商额度。
- 新群默认允许成员互相咨询。旧群保留原权限，需要在成员面板检查「允许群内智能体互相咨询」。私聊开关独立，不需要开启。
- 从 @ 菜单选择真实成员。只有文字声称“已派工”“已通知”不算通过，要看到实际投递、任务和成果。
- 自动化回归使用模拟模型提供方，验证机制；下面的真实模型验收仍需人工执行。

## 1. 智能体创建与单聊

创建「测试-设定检查员」，选择可用模型，说明写「只核对小说设定，不自行补充未确认信息」。保存后重新打开检查配置，再单聊：

> 主角叫沈禾，现实悬疑，没有超能力。请复述三条约束。

接着问：

> 如果让沈禾准确预知明天的案件，符合刚才的设定吗？

预期：配置持久化、实际执行者正确、第二轮引用前文、不无故启动小队。

## 2. 从新建对话选择已有小队

点击「＋」→ 选择小说小队卡片 → 名称填《雨城》→ 创建群聊。

预期：成员和协调员已加入；左侧出现实际群聊；没有独立的「邀请小队」列表；空群不展示必须填写的大表单。通过相同入口再次选择同一个小队可以创建第二个群聊，不覆盖第一个。

## 3. 先讨论，暂不执行

保持「聊天」，发送：

> 我们只讨论，不开始写作。小说《雨城》，主角沈禾，现实悬疑，没有超能力。请先提出三个开篇方向。

再 @ 世界观架构师：

> 请核对上述设定，只做解答，不派工、不写正文。

预期：指定成员回应，没有正式写作交付。若需要严格禁止派工，可显式选择「只讨论」；该模式即使模型尝试开工，宿主也应拒绝创建工作。

## 4. 一句话从聊天开工

回到「聊天」，不指定成员或 @ 协调员，发送：

> 开始，你们自主协作起来。采用刚才确认的《雨城》设定。世界观架构师给三条约束，大纲师给三段大纲，正文写手写约300字首章，编辑审校检查一致性。保留已完成且可复用的内容，提交真实文档，不要只宣布完成，也不要再要求我切换轮次。

预期：

- 协调员整理并保存工作目标，建立真实的协调工作。
- 按需要派出成员任务；依赖就绪后调度执行，而不是靠用户逐个 @ 催促。
- 正式写作使用任务派发，不把整份交付要求塞进只读咨询。
- 成员提交实际成果，协调员被自动唤醒检查，最后进入待验收。
- 同一条开工请求因工具重试不重复建立工作流。

记录实际工作、成员、状态和文档；只有一段模拟多人讲话的文本不算通过。

## 5. 进度询问与 Bot 咨询

在「聊天」发送：

> 现在呢？哪些已经完成，下一步是谁？

预期：核对真实状态并回答，不把问句变成一份新文档交付，也不重新启动整个流程。

单独验证咨询时，选择「只讨论」，@ 正文写手：

> 请通过群内消息工具向世界观架构师核对“沈禾是否有预知能力”。等他真实回复后再回答我，暂时不要写正文。

预期：有写手发给专家的真实投递、专家自己的回答、写手后续总结。正式写作中发生这种咨询时，回答后续做原任务，而不是再建一份重复写作任务。专家失败应明确返回失败，不假装核对成功。

## 6. 同一小队双群并行

A 运行时，点击「＋」再次选择同一小队，创建《星港》。在 B 群聊天确认后开工：

> 开始创作《星港》，主角林朔，太空科幻，飞船名白鹭号。请协作完成约300字开篇并提交文档、审校。

预期：两个群同时保留；切换不暂停；A 的设定、咨询和交付不自动进入 B；A 完成不结束 B。资源不足可以排队，这不是要求用户为了查看另一群而暂停当前群。

## 7. 暂停、刷新与长任务继续

在专用测试群执行中点击「暂停本群工作」，等到「已暂停」，切换 B 确认不受影响。Ctrl+R 刷新，回 A 核对记录与产物，勾选「已核对现有成果与未完成工作」，点击「继续本群工作」。

预期：从未完成的工作继续；保留旧尝试、成果和检查点；不重建群、不把已完成部分全部重跑。等待专家回复的原任务应先处理原咨询。聊天中的“继续”不绕过这个明确的暂停恢复步骤。

可选耐久性验证：先暂停测试群，再从「设置 → 任务 → 守护进程」停止/启动，刷新并核对后继续。不要用正式作品做首次强制结束进程测试。

## 8. 中途加人、局部返工与验收

通过成员面板把「测试-设定检查员」加进 A，再 @ 他：

> 根据本群工作目标和已交付首章，检查主角、题材和能力设定是否一致，只解答。

预期：能利用本群有界上下文，不必手动重贴全部聊天；不会自动进入 B。长消息可以通过执行记录中的回读工具完整读取，不承诺无限历史全部塞进一次模型请求。

随后 @ 写手，选择「分配小工作」：

> 只修改首章最后一段，增加现实可解释的悬疑线索，提交修订版并说明改动。

预期：局部任务与实际修订可追踪；发送成功后回到「聊天」。核对成果并处理所有未完成工作后点击「验收完成」。

## 9. 权限和失败重试（最后测试）

- 关闭测试群的群内咨询开关，验证普通成员间自动咨询受限制；用户 @ 和协调员通信仍可用；私聊权限不被顺带打开。
- 查看真实模型/工具错误对应的执行记录。修复配置后对失败任务「重新执行」，旧尝试保留，不重启其他群。
- 若主动制造模型错误，使用专门的测试智能体/测试模型，不改全局密钥或正式小队配置。
- 文档交付不等于修改项目文件。测试真实写文件时使用独立测试目录和专门智能体，显式配置继承会话权限，仅新增 test-note.txt，检查实际文件。
