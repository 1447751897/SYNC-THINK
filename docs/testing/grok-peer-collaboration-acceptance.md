# 群内 Bot 通信与原任务续做验收

日期：2026-10-01。对应执行协议版本 5。

## 本次实际改动

群内咨询与独立私聊权限拆分；恢复任务群中的真实发信工具；有界回复路由；专家回应后继续原工作；投递/接收者/等待状态可见。没有开放跨群全量记忆、全球 Bot 信箱或任意工作再派发。

## 0. 先加载新后台

1. 先让当前任务结束，或在各任务群主动暂停并确认保存的成果。
2. 在应用「设置 → 任务 → 守护进程」点击「停止」，待停止后点击「启动」，等待 Runtime 就绪。
3. 刷新桌面窗口（Ctrl+R）。若仍显示旧版协作引擎提示，说明后台尚未切换；单独刷新窗口、关闭托盘窗口均不等于重启后台。

本次开发没有强制停止用户的实际守护进程或任务；构建产物在工作区，运行中的旧进程需要上述显式切换。

## 1. 建一个干净测试群

在「邀请小队」点击小说小队的「邀请」。应生成独立新群，成员已加入。点击顶部的群名称/头像（成员入口），确认「允许群内智能体互相咨询」已开启。

- 新群默认开启群内咨询；私聊仍关闭。
- 老群保留原权限，请在这个成员面板明确开启。
- 使用正常可用的模型配置。手动测试真实模型会按你的供应商规则计费；开发验收使用模拟提供方，没有消耗付费模型。

## 2. 先测试纯讨论，不写文件

保留「咨询 / 讨论」，从 @ 菜单选择真实写手成员，然后发送：

> 先不要写正文。请你通过群内消息工具联系世界观架构师，让他核对“主角是否拥有预知能力”。拿到他的回应后，再由你给我最终结论；不要代替他回答。

预期：

- 聊天中出现写手发给专家的真实消息，显示接收者，不是只有正文中的一句 @。
- 专家以自己的身份回答，请求者随后综合回应。
- 能查看每条消息的执行记录、排队/处理中/等待回复/失败状态。
- 该轮为只读讨论，没有新写作任务、没有产物提交。

模型是否主动选用工具有随机性；若只输出“我已经联系”，应查看执行详情。只有真实 `collaboration_send_message` 调用及对应投递记录才算通过。

## 3. 测试“咨询后继续原写作任务”

在任务书中写明：

> 小说 A《雨城》，主角沈禾，现实悬疑，没有超能力。正文作者负责写 300 字首章；动笔前先通过群内消息向世界观架构师核对设定，等对方回答后再完成并提交稿件。主编最终检查，不要代替成员完成全部工作。

保存任务书后点击「开始团队工作」。也可 @ 写手并切换「分配小工作」发出上述具体交付要求。

预期：

1. 写手发出咨询；原工作处于等待成员回复状态。
2. 专家只做咨询，没有获得文件写入/重新派工权限。
3. 回应后，原工作产生下一次执行尝试，工作 ID 保持相同。
4. 最终只有本群对应的首章交付，不多建一份“再写一次”的任务。
5. 专家失败时真实显示错误，请求者收到失败原因，不冒充已核对。

## 4. 同小队并行两本书

再次邀请同一个小队，创建小说 B《星港》，主角林朔，太空科幻。

- 两个群都在左侧，各自有任务书和结果。
- 在 A 咨询/执行时切换 B，B 可以另发咨询或开始工作；容量不足显示排队，不需要为了切换手动暂停 A。
- A 的专家回答和稿件不进入 B 的模型上下文。
- A 完成不会结束 B，切换页面不发送暂停/取消命令。

## 5. 暂停与权限

- 咨询未结束时暂停 A。A 的源工作和关联工作咨询暂停；B 不受影响。
- 勾选核对现有成果后继续 A。先等待原咨询完成，再续做原工作。
- 关闭「允许群内智能体互相咨询」不改变私聊权限。尚未开始的成员间咨询会返回明确失败；正常用户 @ 和协调员通信仍可使用。
- 自动状态通知不要求回应；不会形成“收到/谢谢”的无限互相唤醒。

## v6 补充（2026-10-01）
