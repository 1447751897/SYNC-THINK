# 任务群改造：启动与验收

## 测试前

1. 先保存正在进行的工作，正常停止旧版任务。首次使用新版后台前，建议在服务停止后备份应用数据目录（包括 SQLite 数据及工作区文件）；不要在数据库仍写入时只复制主 `.db` 文件。
2. 在仓库根目录构建并启动：

   ```powershell
   Set-Location D:\projects\SYNC-THINK
   pnpm build
   pnpm dev:desktop
   ```

3. 如果聊天提示“后台仍在使用旧版协作引擎”，进入 **设置 → 任务 → 守护进程**，停止再启动服务。仅刷新、关窗口或重新打开窗口可能仍连接旧 daemon。新接口握手版本为 4。
4. 给小队负责人和成员选择可用模型。第一次建议保持 **只读工作区 · 可交付文档**，先用短章节验证流程，不急着开放命令、外部服务或大规模长篇生成。
5. 新群应显示“任务群”、任务书、状态和“咨询 / 讨论”“分配小工作”。旧群保留历史，有旧工作时默认暂停；先核对任务书和旧任务再决定继续或取消。旧数据不会被主动清空。

## 推荐验收：同一小队写两本小说

### 1. 两个房间，复用同一小队

- 在智能体页面侧栏的 **邀请小队** 区域，点击小说小队的 **邀请**。侧栏 **任务群** 立即出现一个独立群，即使还未发送消息。通过群菜单重命名为“小说 A · 雨城”。
- 任务书：`仅写《雨城》，主角沈禾，现实悬疑。先写一个 300 字章节；完成后等待验收。`
- 再次点击同一小队的 **邀请**，创建第二个独立群，命名“小说 B · 星港”。也可通过任务群标题旁的 + 选择小队及额外智能体。
- 任务书：`仅写《星港》，主角林朔，太空科幻。先写一个 300 字章节；完成后等待验收。`
- 预期：群 ID/聊天记录/任务书/检查点/产物独立，不是把第二本书追加到第一本聊天。两个群应同时直接出现在侧栏，不藏在小队的历史菜单中。点击具体群只是查看；邀请小队始终创建新群，不复用旧群。刷新/重开界面后仍显示两条群记录。

### 2. 先讨论，不自动写作

- 在 A 的“咨询 / 讨论”下 @某个成员：`评价一下这个题材，只讨论。`
- 预期：仅出现答复；无正文写入、无成员自动派工。
- 在 B 同样提问：`本群的书名和主角是什么？`
- 预期：B 不把 A 的沈禾或雨城当作本群设定。可打开任务详情看“本次上下文”，核对 roomId、选中消息和产物引用。运行轨迹中的 context 工具调用才代表后续实际读取。

### 3. 团队开始工作

- A 群保存任务书并点击 **开始团队工作**。A 仍在执行时直接切换 B 群，保存不同任务书并开始工作，全程不点暂停。
- 预期：侧栏同时显示 A/B 的独立状态；来回切换和刷新界面不暂停任何群。A 完成后可显示待验收，B 继续工作。并发槽位或外部写入资源占满时自动排队，不需要靠暂停另一群来切换聊天。
- 预期：负责人先规划/指派具体工作，按需唤起成员；不是每次把整个小队按固定顺序跑一遍。
- 成员提交后，负责人读取产物并再次回报。产物在结果消息/任务详情中可展开；不要只以“我已经完成”的文本判断交付。
- 同一小队可在两群同时工作。若模型并发或外部写入资源有限，任务可以排队，排队不等于串上下文。

### 4. 暂停 A，不影响 B

- 在 A 仍有工作时点击 **暂停本群工作**。
- 预期：先显示“正在暂停”，执行器确认后显示“已暂停”；半成品和旧尝试仍可查看。暂停不标成普通失败。
- 切到 B：应继续运行或独立完成。
- A 暂停时仍可 @咨询，“分配小工作”禁用。
- 重新打开 A 或重启后台：暂停/检查点应保留，不自动把旧工作重新执行。

### 5. 继续 A

- 展开检查点，核对已有输出与实际文件；勾选 **已核对现有成果与未完成工作**，再点 **继续本群工作**。
- 预期：中断的工作产生新尝试，旧尝试留存；已成功的章节不会仅因点击继续就被重跑。失败项需要到任务详情显式重试。
- 若上一轮做过发信、提交、发布等外部操作，先核对外部结果再继续。这里提供“保留状态并继续”，不承诺回滚外部操作或逐 token 精确续写。

### 6. 给 A 加临时顾问

- 打开 A 的成员面板，添加一个不在小队里的 Agent。
- 预期：只加入 A，不改小队定义，不加入 B，也不自动开始执行。
- 在 A 的咨询模式 @顾问：`根据本群已经确认的设定，回答主角叫什么。`
- 再切到“分配小工作” @顾问：`为本群第一章提出 3 个标题，提交文档。`
- 预期：第一条是咨询答复；第二条是单独的工作记录/产物。顾问看的是 A 的群内资料。

### 7. 验收与下一轮

- 工作结束进入 **待验收**。打开实际产物，确认符合任务书，再点 **验收完成**。
- 有失败或未完成项时，验收会被拒绝并显示原因；先重试或明确取消相关工作。
- 同一本书要继续后续章节：更新任务书后发起下一轮，或者在待验收阶段分配局部工作。另一本书仍应创建另一个任务群。
- 文件型产物提交后有独立版本路径；后续修改同名工作文件不应覆盖上一尝试的提交版本。

## 已知边界

- 任务群不是操作系统级沙箱。完全访问工具及第三方 MCP 仍具有其真实权限；文档工作建议先保持只读。
- 公共 Agent 的 persona/skill 是跨群复用配置，请不要把某一本书的专有设定写进去。本群事实放任务书/产物。
- 应用或 daemon 需要运行才能继续推进；此改造未创建定时唤醒服务。
- 关闭再重开窗口与重启 daemon 是两件事。协议提示旧后台时，应按提示重启服务。
- 本轮未用真实在线模型/外部 Codex、Claude SDK 会话进行收费验收；相关真实提供商、断网、授权弹窗和外部副作用仍需在短任务上补验。
- 仓库现有 design-token 检查有 67 条存量告警（主要是未改动的 shell.css、头像和连接器色值）；本次新增任务群样式使用现有主题变量，没有为消除存量告警改动无关界面。
